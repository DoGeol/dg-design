# Table v2 사용성·대량 데이터 계획

> 상태: **로컬 구현 완료** (2026-09-25). 릴리스 승인 전. 인터뷰 9라운드, 계획 범위 모호도 약 8%. [구현 결정](../decisions/2026-09-25-table-v2-implementation.md) · [QA](../qa/2026-09-25-table-v2.md)
> 대상: `@dg-design/react`의 새 데이터 기반 표 계층. 현행 `Table` 마크업 compound는 유지한다.

## 목표와 결정

데이터와 열 정의만으로 표를 만들 수 있게 하고, 필요할 때 `virtual` prop으로 1만 행을 고정 높이 가상 스크롤한다. 첫 단계에는 커스텀 셀, 로컬 정렬·필터·행 선택, 고정 헤더·열을 포함한다. Element 계열의 확장 기능은 뒤 단계에서 추가한다.

| 항목 | 결정 |
| --- | --- |
| 기존 API | `Table.Root/Header/Body/Row/Head/Cell/...`와 named export의 동작·DOM ref·서브패스를 유지한다. 데이터 기반 계층은 별도 `DataTable`로 추가한다. |
| 열 선언 | `columns` prop과 타입이 연결된 render prop `Column` 태그를 둘 다 제공한다. 두 문법은 같은 내부 열 모델로 정규화한다. |
| 직접 자식 태그 | `<DataTable.Column field="..." />`를 기본 API로 제공하지 않는다. 현재 형태로는 부모의 행 타입이 자식에 전달되지 않아 잘못된 필드명을 타입 검사로 잡지 못했다. |
| 지연 처리 | 제너레이터 사용 자체를 요구하지 않는다. 데이터 변환은 순수 함수로 두고, 가상화 시 보이는 행의 셀만 만든다. 정렬·필터가 전체 행을 읽는 비용은 별도로 측정한다. |
| 첫 데이터 경계 | 이미 로드된 배열의 로컬 처리. 서버 페이지네이션·무한 로딩은 후속이다. |
| 첫 가상화 경계 | 세로 행 가상화, 1만 행, 고정 행 높이. 가변 높이·열 가상화는 후속이다. |

기존 [어드민 1차 스펙](../specs/archive/2026-08-19-admin-batch.md)은 Table의 데이터 로직을 수요 실측 후 재고하도록 미뤘다. 이번 계획은 그 재고를 실행하기 위한 새 범위이며, 기존 primitive를 대체하지 않는다.

## 사용 API 초안

두 문법은 동일한 `DataColumn<T>` 계약을 사용한다. `rowKey`는 정렬·필터 이후에도 선택을 보존할 수 있는 안정적인 행 ID다. 아래 prop 이름은 구현 전 타입·런타임 PoC에서 최종 확정한다.

```tsx
// A. 열 배열
const columns: DataColumn<User>[] = [
  { field: "name", header: "이름", sortable: true },
  { field: "status", header: "상태", cell: (user) => <Badge>{user.status}</Badge> },
];

<DataTable
  data={users}
  columns={columns}
  rowKey="id"
  caption="사용자 목록"
  virtual={{ height: 480, rowHeight: 44 }}
/>;
```

```tsx
// B. 행 타입을 DataTable에서 전달받는 Column 태그
<DataTable data={users} rowKey="id" caption="사용자 목록" virtual={{ height: 480, rowHeight: 44 }}>
  {({ Column }) => (
    <>
      <Column field="name" header="이름" sortable />
      <Column field="status" header="상태" cell={(user) => <Badge>{user.status}</Badge>} />
    </>
  )}
</DataTable>;
```

- `field`는 `keyof T`로 검사한다. 계산 열은 별도 `id`와 `cell`을 요구한다. 두 문법에서 열 순서·렌더 결과·정렬·필터·고정 열 동작이 같아야 한다.
- render prop이 반환하는 직접 `Column`, 배열, fragment, 조건부 `null`까지만 지원한다. 임의의 래퍼 컴포넌트 내부를 들여다보거나 `cloneElement`로 데이터 흐름을 만드는 API는 지원하지 않는다.
- `columns`와 render prop을 동시에 주는 사용은 타입에서 막는다. 커스텀 셀 함수와 render prop을 쓰는 예제는 Client Component 경계를 명시한다. 기존 정적 `TableRoot` 등의 서버 소비 경로는 보존한다.

## 처리·렌더링 구조

```text
원본 data
  → 순수 필터 함수
  → 순수 안정 정렬 함수
  → 현재 행 ID/순서 모델
  → virtual=false: 전체 행 / virtual 설정: 화면 범위 + overscan
  → 해당 행의 cell 렌더
```

- 필터는 첫 단계에 텍스트와 열별 선택 옵션을 제공한다. 정렬은 오름차순·내림차순·해제, 필요 시 열별 비교 함수를 허용한다. 행 선택은 `rowKey`로 저장하고 controlled/uncontrolled 양쪽 사용을 지원한다.
- 정렬·필터는 전체 로드 데이터에 각각 O(n log n)·O(n) 비용이 들 수 있다. `useMemo`는 실제 재계산 비용과 참조 안정성을 측정한 곳에만 쓰며, 최초 계산이 지연된다고 설명하지 않는다.
- `virtual`은 기본적으로 꺼진다. 켜면 높이·행 높이를 명시하고 화면 범위만 마운트한다. 셀 렌더러는 범위 밖 행에 대해 호출하지 않는다. 빠른 스크롤과 크기 변경을 다룰 때는 [TanStack Virtual의 행 가상화 패턴](https://tanstack.com/virtual/latest/docs/framework/react/examples/table)을 우선 비교하고, 직접 구현이 더 단순하고 충분한 경우에만 자체 로직을 선택한다.
- 고정 헤더와 좌·우 고정 열은 가상화 켜짐/꺼짐 양쪽에서 동작해야 한다. 고정 열은 offset 계산에 필요한 너비를 명시하게 하고, 줄바꿈으로 고정 행 높이가 깨지는 셀은 잘림·툴팁 등 명시적 표시 규칙을 둔다.
- 네이티브 `<table>` 시맨틱을 우선 유지한다. 가상 행의 위치 지정과 고정 열 때문에 레이아웃이 깨지면 Phase 0에서 렌더 구조를 다시 정하되, 접근성 조건을 낮추지 않는다.

## 단계와 게이트

| 단계 | 작업 | 다음 단계로 가는 조건 |
| --- | --- | --- |
| 0. API·레이아웃 PoC | TypeScript 열 선언 2종, fragment/조건부 열 정규화, 네이티브 table에서 행 가상화+고정 헤더·좌우 열 조합 확인. `@tanstack/react-virtual` 도입 여부 측정 | 잘못된 `field`가 두 문법 모두 컴파일 실패. 1만 행·고정 높이 표에서 고정 요소 정렬과 시맨틱을 유지하는 렌더 경로 확정 |
| 1. 기반 계층 | `DataColumn<T>` 단일 모델과 두 입력 문법, 기본 표·커스텀 셀·빈 결과. 기존 Table CSS/primitive 재사용. 기존 래퍼의 접근성 API 추가 | 두 문법의 DOM·내용 동일, 기존 Table 테스트 무회귀 |
| 2. 표 상태 | 로컬 정렬·텍스트/옵션 필터·행 선택, 제어/비제어 상태와 안정적인 row ID | 조합 순서와 선택 보존, 키보드·스크린리더 이름 검증 |
| 3. 가상화와 고정 요소 | `virtual` prop, 스크롤 컨테이너, overscan, 고정 헤더·좌우 열, 데이터 변경 시 스크롤 위치 정책 | 1만 행 검증, 빠른 스크롤 중 빈 구간 없음, 고정 요소 정렬 유지 |
| 4. 사용 문서·회귀 | Storybook 기본/태그/가상/고정 예제, 두 테마·모바일 VR, 타입 테스트·접근성·브라우저 QA, changeset 준비 | 아래 합격 조건 충족 후 별도 릴리스 승인 요청 |

Phase 0의 타입 미니 PoC는 TypeScript 6.0.3에서 저장소 파일을 만들지 않고 실행했다. 직접 자식 태그의 잘못된 `field`는 통과했고, render prop 태그와 `columns` prop의 잘못된 `field`는 각각 컴파일 오류가 났다. 런타임 열 정규화와 가상 레이아웃 PoC는 아직 하지 않았다.

## 합격 조건

- [ ] `DataTable`의 두 문법에서 정상 필드는 컴파일되고 오타 필드는 컴파일되지 않는다. 커스텀 셀의 `user` 타입이 추론된다.
- [ ] 동일한 열 정의를 A/B로 넣으면 표의 열 순서, 내용, 정렬·필터·선택 결과가 같다.
- [ ] `virtual`을 끄면 전체 행이 표 시맨틱으로 렌더되고, 켜면 1만 행·480px 뷰포트·44px 행 높이·기본 overscan에서 실제 데이터 행 DOM이 30개 이하이다(spacer 제외).
- [ ] 화면 밖 행의 셀 렌더러는 호출되지 않는다. 맨 위·중간·9,000번째 행 이동 시 올바른 행이 보이고 빈 구간이 남지 않는다.
- [ ] 정렬·필터 후 가상 인덱스는 변경된 행 목록을 가리키고, 선택은 배열 인덱스가 아닌 행 ID를 따라간다. 데이터 순서가 바뀌면 스크롤 기준을 예측 가능하게 재설정한다.
- [ ] 가상화 켜짐/꺼짐에서 고정 헤더와 좌·우 고정 열의 위치 및 헤더/본문 너비가 일치한다. 375px과 desktop, 라이트·다크에서 검증한다.
- [ ] 표 이름 또는 caption, 스크롤 영역의 접근 가능한 이름과 키보드 포커스, 정렬 상태, 선택 체크박스의 이름이 제공된다. 가상화 시 전체 행 수와 화면에 있는 행의 실제 인덱스를 일관되게 알린다.
- [ ] 기존 `Table` 객체·named export·DOM ref·CSS와 dg-studio 문서 소비가 회귀하지 않는다. `DDS-A11Y-TABLE`의 스크롤 래퍼 우회를 제거할 수 있는 prop을 제공한다.
- [ ] 빈 데이터·필터 결과 0건·긴 셀·빠른 스크롤·열 고정 조합을 Storybook과 브라우저에서 검증하고, 1만 행의 production build 측정값(마운트 행 수·스크롤 반응)을 기록한다.

## 접근성과 호환성 판단

현행 `TableRoot`는 가로 스크롤 래퍼를 내부에서 만들지만 래퍼에 prop/ref를 줄 수 없다. dg-studio는 `DDS-A11Y-TABLE` 때문에 별도 focusable 영역을 덧씌우고 있다. 먼저 래퍼에 `tabIndex`·접근 가능한 이름·`role="region"`을 전달할 수 있는 좁은 API를 설계한다. 정적 표에 불필요한 탭 정지를 자동 추가하지 않고, 실제로 스크롤하는 DataTable에는 이름 있는 포커스 영역을 제공한다.

가상화로 DOM에 일부 행만 있을 때는 [W3C의 `aria-rowcount`·`aria-rowindex` 규칙](https://www.w3.org/WAI/ARIA/apg/practices/grid-and-table-properties/)을 따른다. 단순 표는 `role="grid"`로 바꾸지 않는다. 행이 언마운트될 때 포커스가 사라지지 않도록 키보드 스크롤·선택 시나리오를 브라우저와 보조 기술로 검증한다.

## 후속 단계와 제외 범위

첫 단계에서는 서버 페이지네이션·무한 로딩, 가변 행 높이, 열 가상화, 확장 행, 트리, 그룹 헤더, 요약 행, 셀 병합, 열 크기 조절·순서 변경을 구현하지 않는다. 이들은 [Element 계열 Table 문서](https://github.com/element-plus/element-plus/blob/dev/docs/en-US/component/table.md)의 폭넓은 기능 목록을 기준으로 후속 수요와 가상화 호환성을 각각 검토한다. 특히 확장·트리·병합은 고정 높이 가상화와 별도 설계가 필요하다.

## 참조

- [Element UI Table](https://element.eleme.io/#/en-US/component/table) — 사용자가 제시한 태그형 UX 참조. 원본 페이지는 브라우저 실행형 문서라 정적 내용 비교에는 위 Element Plus 문서를 함께 사용했다.
- [React `Children` 문서](https://react.dev/reference/react/Children) — 자식 순회는 내부 컴포넌트의 렌더 결과와 fragment 내부를 자동으로 읽지 않으며, 배열 prop·render prop을 대안으로 제시한다.
- [React `useMemo` 문서](https://react.dev/reference/react/useMemo) — 큰 배열 변환의 재계산을 줄일 때 측정 후 적용한다.
- [TanStack Table 가상화 가이드](https://tanstack.com/table/latest/docs/framework/react/guide/virtualization) — 데이터 모델과 가상 렌더링을 분리하고, 고정 높이부터 시작하도록 안내한다.
