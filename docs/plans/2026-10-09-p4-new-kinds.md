## 검증

`pnpm generate` → `pnpm build` → react test → `pnpm typecheck` → publint → `check:subpaths` → 로컬 VR(기능 테스트만, 시각 비교는 linux 기준이라 skip). 시각 기준은 PR 뒤 `visual-baseline` 워크플로로 만든다 — **MultiSelect·Select 기준은 먼저 지우고** 다시 찍는다(0.5% 임계에 묻힘 방지). 새 스토리 기준은 처음 생성.

## 커밋·배포 (단계마다 승인)

## 위험과 대응

- `use-overlay-position`의 폭 맞춤은 `matchTriggerWidth`를 켠 Select·MultiSelect가 같이 쓴다. 변수가 없으면 `max(트리거, 0px)` = 지금과 같아 기존 동작이 바뀌지 않는다.
- 투명 `::before`가 소비자 Button 의사요소와 겹치는지: Button CSS는 현재 의사요소를 쓰지 않는다(확인). 겹치는 소비자가 생기면 Trailing 래퍼로 옮긴다.
- 파일 상한: List가 500줄을 넘으면 section 파일로 이미 나눠 둔다.
