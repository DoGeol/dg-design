## 목표

dg-studio 같은 소비 앱이 객체 목록, 사용자가 고른 값과 필터, 값을 고르는 속성 행을 직접 만들지 않고 DDS의 `list`·`chip`·`filter-toolbox`·`property-field` 하위 경로와 역할 토큰으로 조립할 수 있게 한다. 접근성 계약(링크·버튼 분리, aria-pressed, 라벨 연결, live region)과 모바일 44 조작 영역을 컴포넌트가 책임진다.

## API

### 1. List (`@dg-design/react/list`)

```tsx
<List.Section collapsible defaultOpen>
  <List.SectionHeader as="h2" title="전체 버전" count={3} description="…" action={<Button …>버전 추가</Button>} />
  <List.Root>
    <List.Item current>
      <List.Leading><Avatar.Root …/></List.Leading>
      <List.Action href="/posts/d1">다크 모드 대비 검수 메모</List.Action>
      <List.Meta>접근성 · 10월 5일 수정</List.Meta>
      <List.Trailing><Badge …/><DropdownMenu.Root>…</DropdownMenu.Root></List.Trailing>
    </List.Item>
    <List.Item>
      <List.Title>이력서 v2</List.Title>              {/* 행 기본 행동이 없는 정적 행 */}
      <List.Meta>…</List.Meta>
      <List.Trailing>…</List.Trailing>
    </List.Item>
  </List.Root>
</List.Section>
```

- `List.Root`: `ul role="list"`(Safari가 `list-style: none` 목록 의미를 지우는 것 복원). listbox·grid 의미를 붙이지 않는다. Section 안이면 Section의 content id를 받고 닫혔을 때 `hidden`.
- `List.Item`: `li`. `current?: boolean` → Action(없으면 li)에 `aria-current="true"` + `bg-neutral-weak`.
- `List.Action`: 행 기본 행동. `href`가 있으면 `a`, 없으면 `button type="button"`. `asChild` 허용(Next `Link` 등). `::after`가 행 전체를 덮어 누름 영역이 된다. 이름은 전체 제목(말줄임은 CSS만).
- `List.Title`: 기본 행동이 없는 행의 제목(정적 `span`).
- `List.Leading`·`List.Meta`·`List.Trailing`: 클래스만. Trailing은 행 링크 위(z-index) 형제라 링크 안에 버튼이 중첩되지 않는다. 탭 순서 행 Action → Trailing 버튼 → 다음 행.
- 행 높이: Meta가 있으면 `--dds-size-list-row-2`, 없으면 `--dds-size-list-row-1`(`:has(.dds-list__meta)`). 좌우 `--dds-space-list-inset`, leading 간격 `--dds-space-list-leading-gap`.
- 외관(B): 투명 표면, 카드 아님. 행 사이 1px `stroke-neutral-weak`(좌우 여백에서 시작). 제목 fg-neutral(두 줄 행은 bold), 메타 t3 fg-neutral-weak(모바일 t4). hover `bg-transparent-hover`·pressed `bg-transparent-pressed`는 Action이 있을 때만, trailing 버튼 위에서는 행이 반응하지 않는다. focus는 Action에 행 안쪽 2px 링(비입력 계약).
- `List.Section`: context(열림 상태·content id). `collapsible?`, `open`·`defaultOpen`(기본 true)·`onOpenChange`. 접기 없는 Section은 context만 묶음 제목과 목록의 `aria-labelledby` 연결에 쓴다.
- `List.SectionHeader`: `title`·`count?`·`description?`·`action?`·`as?: "h2"|"h3"|"h4"`(기본 h3). collapsible Section 안이면 heading 안에 접기 `button`(`aria-expanded`·`aria-controls`, chevron). action은 heading 밖 형제다. 최소 높이 40, 제목 t3 bold fg-neutral-weak, 건수 regular.
- export: 객체 + `ListRoot`·`ListSection`·`ListSectionHeader`·`ListItem`·`ListLeading`·`ListAction`·`ListTitle`·`ListMeta`·`ListTrailing`.

### 2. Chip·FilterChip (`@dg-design/react/chip`)

```tsx
<Chip leading={<Avatar.Root …/>} onRemove={remove} removeLabel="김도걸 제거">김도걸</Chip>
<FilterChip pressed={mine} onPressedChange={setMine}>내 글</FilterChip>
```

- `Chip`: `span` leaf. `leading?`, `disabled?`. `onRemove`를 주면 `removeLabel`이 타입에서 필수(판별 유니언). 칩 자체는 초점을 받지 않고 제거 버튼만 받는다.
- 제거 후 초점: 같은 부모 안 다음 칩의 제거 버튼 → 이전 칩의 제거 버튼. 둘 다 없으면 Chip은 옮기지 않고 소비자 몫이다(MultiSelect는 검색 입력으로).
- 순서: Chip이 형제 제거 버튼을 찾아 **먼저 초점을 옮긴 뒤** `onRemove`를 부른다. `onRemove`의 상태 갱신이 칩을 언마운트하면 초점이 body로 떨어지기 때문이다. MultiSelect의 입력 이동은 값이 비었을 때만 상태가 정리된 뒤 한다.
- `FilterChip`: `button[aria-pressed]` leaf. `pressed`·`defaultPressed`·`onPressedChange`. 켜짐은 색만이 아니라 체크 아이콘으로도 표시. 제거 버튼을 품지 않는다(button 안 button 금지).
- 외관(B): 값 칩 bg-neutral-weak·fg-neutral·테두리 없음. leading 크기는 소비자가 고른다(구현에서 "칩 높이 − 4" 강제 규칙은 뺐다 — Avatar 크기 축을 칩이 덮지 않는다). 제거 버튼 fg-neutral-weak, hover bg-transparent-hover. 필터 칩 꺼짐 bg-layer-default + 안쪽 1px stroke-neutral-weak, 켜짐 bg-brand-weak + fg-brand(+hover brand-weak-hover). 높이 `--dds-size-chip-height`, 반경 `--dds-radius-chip`, 글자 t2/t3(모바일), 좌우 8/12(제거 버튼 쪽 0). disabled는 bg-disabled.
- MultiSelect: `multi-select-search.tsx`의 비공개 칩을 `Chip`으로 바꾸고 `dds-multi-select__chip*` CSS를 지운다. `formatRemoveLabel`은 그대로 `removeLabel`로 흐른다. 마지막 칩을 지우면 초점은 검색 입력으로.

### 3. FilterToolbox (`@dg-design/react/filter-toolbox`) + Select chip 트리거

```tsx
<FilterToolbox.Root aria-label="글 필터">
  <FilterToolbox.Chips>
    <Select.Root value={status} onValueChange={setStatus}>
      <Select.Trigger variant="chip" active={status !== "all"} aria-label="상태">상태: {statusLabel}</Select.Trigger>
      <Select.Content>…</Select.Content>
    </Select.Root>
    <FilterChip pressed={mine} onPressedChange={setMine}>내 글</FilterChip>
  </FilterToolbox.Chips>
  <FilterToolbox.Count>12개</FilterToolbox.Count>
  <FilterToolbox.Actions><Button size="small" intent="neutral" variant="ghost" disabled={isDefault}>초기화</Button></FilterToolbox.Actions>
</FilterToolbox.Root>
```

- 껍데기 compound(구성 규칙 1단계 — 문구·초기화 행동은 앱 소유). context 없음, 클래스만.
- `Root`: `role="group"`, 이름은 `aria-label`/`aria-labelledby`(타입에서 둘 중 하나 필수). `Chips`: 칩 줄(가로 간격 6, 모바일 줄 간격 12). `Count`: `role="status"`(aria-live 없음). `Actions`: 오른쪽 끝. 모바일은 Count·Actions가 다음 줄.
- 고정 필터는 제거 버튼 없이 값만 바꾸고, 추가한 필터만 `Chip onRemove`를 단다 — 사용 규칙으로 문서화.
- `Select.Trigger variant="chip"`: 칩 높이·반경, caret 유지, `active?: boolean`이면 필터 칩 켜짐 색. combobox 계약 그대로. chip일 때 패널 폭은 트리거 폭과 최소값 중 큰 쪽이다(지금 `matchTriggerWidth`로 약 90px가 되는 문제, gaps §13). 최소값 12rem은 **제안값**이다 — R9는 숫자 없이 방식만 정했다. 기본 variant 동작은 불변.

### 4. PropertyField (`@dg-design/react/property-field`)

```tsx
<PropertyField.Group aria-label="발행 설정">
  <PropertyField.Root>
    <PropertyField.Label>공개 범위</PropertyField.Label>
    <Select.Root defaultValue="link">
      <Select.Trigger />
      <Select.Content>…</Select.Content>
    </Select.Root>
  </PropertyField.Root>
  <PropertyField.Root>
    <PropertyField.Label>발행 시각</PropertyField.Label>
    <Popover.Root>
      <Popover.Trigger asChild><PropertyField.Trigger placeholder="선택">{publishAt}</PropertyField.Trigger></Popover.Trigger>
      <Popover.Content>…</Popover.Content>
    </Popover.Root>
    <PropertyField.ErrorMessage>발행 시각을 고르세요</PropertyField.ErrorMessage>
  </PropertyField.Root>
</PropertyField.Group>
```

- 텍스트 입력이 아니라 값을 고르는 트리거다. Select형은 combobox, Popover·Sheet형은 `PropertyField.Trigger`(button, `aria-expanded`는 Popover.Trigger가 단다). Popover 패널이 `role="group"`이라 `aria-haspopup="dialog"`는 달지 않는다.
- `Root`는 `Field.Root` 위에 만든다. FieldContext의 input id를 `PropertyField.Trigger`가 자기 id로 써서 `Label`의 `for`가 Popover 트리거에도 닿는다(gaps §13 "Field.Label for가 Popover 트리거에 안 닿음" 해결, Field 공개 API는 불변). Select는 이미 FieldContext를 읽는다.
- `Trigger`: 값(children) 또는 placeholder(fg-neutral-weak) + caret. 이름은 `aria-labelledby="{라벨} {값}"`으로 "라벨 + 현재 값"이다(button은 라벨이 있으면 내용을 이름에 쓰지 않는다). 오류는 ErrorMessage가 있을 때(Field 규칙) `aria-invalid`.
- `Label`·`Description`·`ErrorMessage`는 Field의 것과 같은 컴포넌트(ContextMenu 별칭 방식).
- 행 안 Select 트리거는 `.dds-property-field` 아래 CSS로 값 영역 모양(테두리 없음)이 된다. 패널은 값 영역(트리거) 기준으로 열린다 — 별도 anchor API 없음.
- 배치(두 밀도 모두 행, R4):
  - 데스크톱: 테두리 없는 행, 높이 `--dds-size-setting-row-height`(48), 라벨 왼쪽 1/3 열 fg-neutral-weak, 값 fg-neutral 왼쪽 정렬, hover bg-transparent-hover, 반경 `--dds-radius-field`. focus는 행 안쪽 2px 링(비입력). Group은 표면 없이 쌓는다.
  - 모바일: Group이 bg-neutral-weak 표면(`--dds-radius-setting-row` 14) 안에 56 행을 쌓는다. 라벨 fg-neutral 16 왼쪽, 값 오른쪽 정렬 fg-neutral-weak, 행 사이 1px stroke-neutral-weak는 안쪽 16에서 시작.
  - error: 행 안쪽 1px stroke-critical(focus 시 2px) + 행 아래 ErrorMessage. disabled: bg-disabled + fg-disabled.
- `Group`: `role="group"` + 이름 필수.

### 6. 모바일 조작 영역 44

- 보이는 크기는 유지하고 `[data-dds-density="mobile"]`에서 투명 의사요소로 `--dds-size-touch-target` 정사각 영역을 만든다: Chip 제거 버튼(32), FilterChip(높이 32), `List.Trailing` 안 `button`·`a`(36), List SectionHeader 접기·action 버튼.
- 겹침 방지: 칩 줄 가로 간격 6(제거 버튼 확장 6이 이웃 칩 가장자리까지만 닿는다), 모바일 줄 간격 12.
- 데스크톱 24는 시각 크기(칩 24, 버튼 36)가 이미 넘는다.

## 제약

- 기존 공개 API 동작 불변. MultiSelect는 칩 DOM 클래스만 바뀌고 역할·이름·키보드는 같다(기존 테스트 통과, 선택자만 갱신).
- 새 CSS는 `@layer dds`, 역할 토큰만 참조(대체값 없음). `hidden` 요소는 자기 display 옆에 `[hidden] { display: none }`.
- compound는 객체 + named export. 배럴은 감독만 수정. 하위 경로 4개는 `check:subpaths` 가드를 통과.
- 파일 300~500줄 상한 — List는 section 파일을 분리할 수 있다.
- 배포 한 번(R6): 스펙 하나, PR 하나, tokens + react minor, VR 기준 1회 갱신.
- 하위 경로는 계획표의 3개가 아니라 4개다. FilterToolbox는 Select와 함께 쓰는 조합이라 `chip`에 넣으면 Chip만 쓰는 소비자도 Select 경로를 끌어오게 되어 따로 둔다.
- PropertyField 행은 테두리를 지운다. 결정 기록의 "입력 경계 1px은 접근성 계약(WCAG 1.4.11)"은 텍스트를 쓰는 입력의 경계다. 속성 행 트리거는 선택창을 여는 버튼이고, 라벨 열·caret·행 구분선·hover 표면이 조작 대상임을 보인다. 오류 행은 1px stroke-critical로 경계를 되살린다.

## 하지 않을 것

- List 선택 모드(보류 구성요소), 가상화, 드래그 정렬, 무한 스크롤.
- loading(Skeleton 행)·empty(StatePanel) 전용 부품 — 소비자가 기존 컴포넌트로 조합.
- PropertyField read-only 정적 행, box 배치(A), `layout` prop.
- 설정 행(Switch·Radio 행) 컴포넌트 — 토큰은 PropertyField가 먼저 읽는다.
- FilterToolbox의 문구·초기화 로직·필터 추가 메뉴.
- Select의 일반 `anchor`·`minWidth` 공개 prop(chip variant 안에서만 패널 최소 폭).
- 시안 `apps/storybook/src/mockups/flex/proto/*`와 Scenarios 교체·삭제(R10) — 결정 당시 비교 기록으로 남긴다.
- dg-studio 전환(저장소 밖).

## 합격 조건

- [x] **List**: `ul`이 role=list. `List.Action href`는 링크, 없으면 button. Trailing 버튼은 Action 밖 형제이고 탭 순서 Action → Trailing. `current`면 `aria-current="true"`. collapsible Section의 접기 버튼은 `aria-expanded`·`aria-controls`가 목록 id를 가리키고, 누르면 목록이 `hidden`. 비제어 `defaultOpen`·제어 `open/onOpenChange` 둘 다 동작.
- [x] **Chip**: 제거 버튼 이름이 `removeLabel`, 누르면 `onRemove` 한 번, 초점이 다음 → 이전 칩 제거 버튼으로. disabled면 제거 안 됨. `onRemove` 있고 `removeLabel` 없으면 타입 에러(타입 테스트 또는 `@ts-expect-error`).
- [x] **FilterChip**: `aria-pressed`가 상태를 따르고 제어·비제어 토글, 켜짐에 체크 아이콘.
- [x] **MultiSelect**: 칩이 `Chip`으로 렌더되고 기존 테스트 전부 통과. 마지막 칩 제거 뒤 초점이 검색 입력.
- [x] **FilterToolbox**: Root가 이름 있는 group, Count가 status.
- [x] **Select chip**: `variant="chip"` 트리거가 combobox, `active`가 켜짐 표시. 열린 패널 폭 ≥ 12rem. 기본 variant 패널 폭은 트리거 폭 그대로.
- [x] **PropertyField**: Label 클릭이 Select·Popover 트리거 모두에 초점/열기. Popover 트리거의 접근 이름이 "라벨 + 값". ErrorMessage가 있으면 트리거에 `aria-invalid`, 설명·오류가 describedby에 연결. Group이 이름 있는 group.
- [x] **토큰**: 6개가 tokens.css `:root`에 있고 mobile 값이 다른 4개(list-row-1·list-row-2·list-inset·setting-row-height)만 밀도 블록에 있다(`create-theme.check` 통과). Tailwind 브릿지에 유틸 생성.
- [ ] **VR**: `List`·`Chip`·`FilterToolbox`·`PropertyField` `*--state-matrix` 스토리(데스크톱·모바일·다크 포함), Select 상태 매트릭스에 chip variant. MultiSelect 기준은 지우고 다시 찍는다.
- [x] **모바일 44**: 모바일 밀도에서 Chip 제거 버튼·FilterChip·Trailing 버튼의 `elementFromPoint` 히트 영역이 44 이상(VR 기능 테스트 1개).

## 남은 위험

- **소비처 없는 API**: FilterToolbox·Select chip·PropertyField는 실사용 없이 시안만으로 정했다. 첫 실사용(dg-studio 전환)에서 API가 맞지 않으면 다음 minor에서 바꿀 수 있게 changeset·customization에 "초기 API"라고 적는다.
- 투명 확장 의사요소가 소비자 Button 자체 의사요소와 충돌할 수 있다(List.Trailing 안 Button). 구현에서 Button CSS를 확인하고 충돌하면 Trailing 래퍼 쪽에서 영역을 만든다.
- Select chip 패널 최소 폭 12rem은 제안값이다. 상태 매트릭스 스토리에서 가장 긴 옵션이 줄바꿈 없이 들어가는지 보고 확정한다.
- 데스크톱 PropertyField 행(48)이 같은 화면의 TextField(40)보다 높다 — 섞인 폼에서 리듬이 어긋날 수 있다. Storybook 스토리로 확인한다.
- 실기기 터치·스크린리더 청취(Popover형 이름, Count status)는 jsdom·VR 밖이다.
