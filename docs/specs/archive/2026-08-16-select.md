## 목표

TextField 외관의 버튼 트리거와 DropdownMenu 로직 재사용으로 폼 단일 선택 Select(typeahead 포함)를 만들고 Field에 연동해 0.7.0으로 릴리스한다.

## 제약

**헤드리스 로직** (`packages/react/src/select/` — 훅 파일 분리 관습)
- **roving 재사용**: DropdownMenu의 DOM 조회 roving 그대로, role만 `listbox`/`option`(aria-selected). 열릴 때 **선택된 옵션에 포커스 + scrollIntoView**, 없으면 첫 옵션
- **typeahead**: 문자 버퍼 + 1초 타임아웃. 열린 상태 = 포커스 이동, **닫힌 상태 = 값 직접 변경**(네이티브 관례). 대소문자 무시 prefix 매치
- **닫힌 상태 화살표·Enter·Space = 열기만** — 값 변경은 열린 상태에서만 (Radix·APG)
- 상태: `value`/`onValueChange`/`defaultValue` — useControllableState 재사용. placeholder는 value 없을 때 트리거에 회색 표시
- 선택 시 닫힘 + 트리거 포커스 복귀. 외부 클릭·ESC dismissal — DropdownMenu 로직(mousedown+트리거 제외·비모달 스택 등록) 재사용
- floating: DropdownMenu와 동일(@floating-ui/dom, bottom-start, offset·flip·shift). 패널 min-width는 **트리거 너비 이상**(size 미들웨어 위임)

**Select 컴포넌트**
- compound 6종: `Root`·`Trigger`·`Content`·`Option`·`Group`·`Label`. barrel엔 Select 하나
- Trigger: `<button>` — **TextField 동형** 외관(stroke-neutral 테두리·size medium/large·placeholder 회색·disabled 3중 매칭), 오른쪽 caret 인라인 SVG(열림 시 회전 위임), `role="combobox"` `aria-expanded` `aria-haspopup="listbox"`
- invalid: Field context 소비 → `stroke-critical` 테두리 + aria-invalid (TextField와 동일 경로)
- Option: `value` 필수·disabled 지원, 선택 표시(체크마크 인라인 SVG 또는 강조 — 위임). Group·Label은 DropdownMenu 관례 대칭
- CSS: `@layer dds`, 패널·애니메이션은 DropdownMenu와 동일 계열(duration-fast), reduced-motion 대응. 치수 위임

**Field 연동**
- Field.Label 클릭 → 트리거 포커스(htmlFor는 button에도 유효), describedby·invalid 자동 — TextField의 context 소비 코드 패턴 재사용

**폼 제출**
- `name` prop 있으면 `<input type="hidden" name value>` 렌더 — 네이티브 폼 호환. 없으면 미렌더

**테스트·VR**
- vitest: value 상태(controlled/uncontrolled), 열림 시 선택 옵션 포커스, typeahead(열림·닫힘 양쪽, 타임아웃 fake timers), 닫힌 화살표=열기만, 선택 닫힘·복귀, hidden input, Field 연동(label 클릭·invalid), disabled 옵션 건너뜀, aria(combobox·listbox·selected)
- Playwright 기능 3~4: 열기→화살표→Enter 선택 값 반영, typeahead 점프, 외부 클릭, Field label 클릭 포커스
- VR: 열림 고정 스토리 라이트·다크. 스토리 id 규약: `select--functional-demo`·`select--with-field-demo`
- changeset frontmatter 인용 필수

## 하지 않을 것

- 다중 선택 — 별개 MultiSelect(트리거 표시·해제 UX가 다른 물건). value는 string 고정
- 검색형(combobox 입력 필터) — 별개 컴포넌트
- 닫힌 상태 화살표 값 변경 — 열기만 (typeahead는 예외적으로 값 변경, 네이티브 관례)
- 네이티브 `<select>` 폴백·모바일 시트 — 버튼 셀렉트 단일 형태
- Option 커스텀 렌더 슬롯(아이콘 등) — children 자유라 불필요
- 가상 스크롤 — 수백 옵션은 max-height 스크롤로

## 드러난 가정과 결론

| 가정 | 어떻게 흔들었나 | 결론 |
|------|----------------|------|
| Select 관례는 activedescendant | roving 재사용 비용 비교 | roving + role listbox (Radix 실질 동일) |
| 다중 선택 대비 배열 설계 | 반론 — UX 자체가 다른 물건 | value: string 고정, MultiSelect는 별개 |
| typeahead는 열린 상태만 | 네이티브 select 관례 제시 | 닫힌 상태 값 변경까지 도입 |
| 닫힌 화살표 = 네이티브 동형 | 단순화 — 실수 변경 위험 | 열기만 |

## 기술 맥락

- `packages/react/src/dropdown-menu/` — roving·floating·dismissal·portal·단일열림 재사용 원본. **공유 로직은 복제 대신 추출 검토**(roving-focus.ts를 internal로 이동 등 — 구현 판단, ownDecisions)
- `packages/react/src/text-field/text-field.css` — 트리거 외관 원본
- `packages/react/src/field/` — context 소비 패턴 (TextField.tsx 참조)
- dialog-stack 비모달 등록 — DropdownMenu와 동일
- 기존 테스트 48건 무회귀 게이트

## 남은 위험

- roving-focus 등 공유 로직을 internal로 옮기면 dropdown-menu 경로 수정 발생 — 이동 시 기존 테스트로 회귀 확인
- typeahead 닫힌 상태 값 변경과 "닫힌 화살표 열기만"의 공존 — 키 이벤트 분기 명확히 (문자 키만 값 변경)
- 트리거 라벨이 옵션 children에서 오는데 value만 아는 상태에서 라벨 역참조 필요 — Radix식 ItemText 등록 또는 옵션 스캔 (구현 판단)
