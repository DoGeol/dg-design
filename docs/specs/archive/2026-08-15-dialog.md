## 목표

중첩과 열림/닫힘 애니메이션을 갖춘 자체 구현 Dialog를 헤드리스 훅 + 스타일 껍데기 구조로 만들고, 오버레이·그림자·모션 토큰을 신설해 0.5.0으로 릴리스한다.

## 제약

**헤드리스 로직층** (`packages/react/src/dialog/` 내 훅 파일 분리 — 파일 규칙 첫 적용: `use-dialog.ts`·`use-presence.ts`·`dialog-stack.ts` 류 로직 파일 + `Dialog.tsx` 스타일 껍데기)
- **presence**: 닫힘 → 퇴장 애니메이션 → `animationend/transitionend` 대기 후 unmount, 안전 타임아웃 폴백(값 위임). 애니메이션 정의는 CSS에만 존재
- **중첩 스택**: 모듈 레벨 싱글턴 — 열릴 때 push·닫힐 때 pop. ESC는 최상단만 닫는다. 스크롤 잠금은 refcount(첫 진입 잠금·마지막 이탈 해제). seed layer-stack과 동형
- **focus trap = 배경 inert**: 열릴 때 portal 형제들 + 스택상 이전 다이얼로그에 `inert` 부여, 닫힐 때 복원. Tab 순환 코드 없음
- **상태**: controlled(`open`+`onOpenChange`)/uncontrolled(`defaultOpen`) 겸용 — useControllableState 훅
- **포커스**: 열릴 때 Content(tabIndex=-1) 기본, `initialFocusRef`로 오버라이드. 닫힐 때 열기 전 포커스 요소로 복귀
- **dismissal**: ESC·오버레이 클릭 기본 닫힘, 각각 끄는 prop 제공(이름 위임)

**Dialog 컴포넌트**
- compound 7종: `Dialog.Root`(상태·context)·`Trigger`·`Overlay`·`Content`·`Title`·`Description`·`Close`. barrel엔 `Dialog` 하나만
- `createPortal`로 body 직속 렌더. Content에 `role="dialog"` `aria-modal="true"`, Title/Description은 Field 패턴처럼 id 자동 연결(`aria-labelledby`/`aria-describedby` — 렌더된 것만)
- **오버레이 누적**: 다이얼로그마다 자기 Overlay, 중첩 시 겹침(seed와 동일). 스택-오버레이 연동 로직 없음
- **on/off 애니메이션**: 열림·닫힘 모두. 사양(fade/scale 조합) 위임, duration·easing은 신설 모션 토큰 참조, `prefers-reduced-motion: reduce`에서 제거
- Content 치수·패딩·radius 위임(기존 dimension/radius 토큰). shadow-overlay·bg-layer-default 사용

**토큰** (`packages/tokens`)
- `bg-overlay` — 오버레이 막. gray-1000/알파, 모드별 알파 위임. 대비 검사 없음(gamut만)
- `shadow-overlay` — 첫 그림자 토큰. 비색상 취급(모드 분기 필요하면 semantic 편입 판단 위임)
- **모션 토큰**: `duration-fast`(≈150ms)·`duration-base`(≈200ms) + easing 1~2종. 실값 위임. **Switch·Checkbox의 150ms 하드코딩을 duration-fast 참조로 소급 교체**
- 시스템 그림자 스케일(sm/md/lg)은 만들지 않는다 — 소비자 오면

**react-dom peer**
- `peerDependenciesMeta.react-dom.optional` 제거(0.2.0에 걸어둔 것). changeset에 명시

**테스트·VR**
- vitest(jsdom): 스택 push/pop·ESC 라우팅 로직, presence 타임아웃(fake timers), controllable state, aria 연결, inert 속성 부여. user-event 관습 유지
- **Playwright 기능 테스트 3~5케이스**(apps/visual-regression에 기능 spec 추가 또는 인접 배치 — 배치 위임): 실브라우저에서 열기→ESC→포커스 복귀, 중첩 ESC 최상단만, 백드롭 클릭, inert 실효
- VR 스크린샷: 열림 고정 스토리(open 항상 true) — 동적 열거가 자동 편입, 라이트·다크

## 하지 않을 것

- 네이티브 `<dialog>`/`showModal` — 사전 토론에서 탈락 (자체 구현 채택)
- 스택-오버레이 연동(항상 한 장) — 누적 채택
- Tab 순환 트랩 — inert로 대체
- 그림자 시스템 스케일(sm/md/lg) — 소비자 1개, YAGNI
- AlertDialog(role=alertdialog) 변형 — 수요 시 별도
- Sheet/Drawer류 — 별개 컴포넌트
- exit 애니메이션의 Web Animations API — CSS 주도 유지

## 드러난 가정과 결론

| 가정 | 어떻게 흔들었나 | 결론 |
|------|----------------|------|
| 퇴장은 duration 고정이 단순 | CSS 이중 관리 지적 | 이벤트 대기 + 타임아웃 폴백 |
| Trigger 채택 = 겸용 자동 | 반론 — controlled 전용이면 로직 절감 | 겸용 유지 (사용자 확정) |
| focus trap = Tab 순환 | 단순화 — 바깥을 끄는 inert 제시 | inert 방식 채택 |
| 그림자 스케일 미리 필요 | intent 축 때의 "소비자 있는 것만" 논리 재적용 | overlay용 2개만 |
| 오버레이는 한 장이 깔끔 | seed 실코드 확인 요청 → 누적 확인 | 누적 (seed 동일) |
| 모션 하드코딩 유지 | 소비자 2개째 도달 지적 | 토큰 신설 + 소급 교체 |
| jsdom으로 충분 | 포커스·inert 실효 검증 불가 지적 | Playwright 기능 테스트 병행 |
| 초기 포커스 Content 고정 | 폼 다이얼로그 편의 문제 제기(사용자) | 기본 Content + initialFocusRef |

## 기술 맥락

- `packages/react/src/field/` — compound·context·aria 연결 패턴 원본 (Title/Description 연결에 재사용)
- `packages/react/src/internal/merge-refs.ts` — 재사용
- seed 참조(read-only): `react-headless/dialog/`(useDialog·backdropProps 구조), `react-headless/dismissible-layer/layer-stack.ts`(싱글턴 스택)
- `apps/visual-regression` — 동적 열거라 열림 고정 스토리 추가만으로 VR 편입. 기능 spec 추가 시 기존 playwright.config 활용
- vitest fake timers — presence 타임아웃 테스트
- 기준 이미지 갱신은 visual-baseline 워크플로 경유 (Switch 토큰 교체분 시각 무변화 확인 포함)

## 남은 위험

- inert의 jsdom 동작이 불완전할 수 있음 — vitest에서는 속성 존재만, 실효는 Playwright
- presence 타임아웃 폴백값과 CSS duration 불일치 시 애니메이션 절단 — 토큰 단일 소스로 완화되나 폴백 마진 설계 필요
- Switch 150ms → duration-fast 교체가 VR diff를 낼 수 있음(값이 동일하면 무변화 — 실값 위임 시 150ms 유지 권장)
- 포커스 복귀 대상이 unmount된 경우(리스트에서 열고 항목 삭제) — body 폴백 등 방어 필요
- 이번 릴리스 최대 규모 — 태스크 분해에서 로직층과 컴포넌트를 한 에이전트가 맡을지(같은 디렉터리) 주의
