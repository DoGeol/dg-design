## 목표

이미지·카드처럼 폭이 있는 항목을 한 줄로 늘어놓고 스와이프·드래그·버튼·키보드로 넘기는 표면을 제공한다.
스크롤·스냅은 브라우저에 맡기고, DDS는 현재 위치 추적, 이전·다음, 인디케이터, 접근성 배선을 소유한다.
슬라이드 안의 내용(이미지·링크·카드)과 로딩 표현은 소비자가 채운다.

## 하지 않을 것

- 자동재생·자동 회전(아래 §자동재생에 도입 시 계약만 예약).
- 무한 루프를 위한 슬라이드 복제, 3D·페이드·카드 쌓기 같은 전환 효과.
- 세로 방향(첫 버전은 가로만), 썸네일 스트립, 줌·라이트박스.
- 탭 패널 전환(Tabs), 값 슬라이더(Slider), 페이지 번호 이동(Pagination)의 대체.
- 마우스 휠로 가로 이동 가로채기, 슬라이드 높이 자동 맞춤.

## 구성요소와 소비처

| 구성요소 | 형태·독립 기능 | 예상 소비처 (미확인) |
| --- | --- | --- |
| Root | compound + context · 값, 등록, id 연결 | 블로그 글 본문 이미지 갤러리, 관련 글 카드 한 줄 |
| Viewport·Slide | 스크롤 컨테이너 + 항목 | 랜딩 쇼케이스 섹션, 이력서 프로젝트 스크린샷 |
| Previous·Next | 버튼 | 위 전부 |
| Indicators | 위치 점 | 슬라이드 3~8개인 갤러리 |

구성 규칙 판별: 사용처마다 슬라이드 구성이 달라지고(2), 값·키·id 연결을 공유하므로(3) compound + context다.
**게이트:** 승인 전에 dg-studio에서 독립 소비처 두 곳을 확인한다. 하나뿐이면 승격하지 않고 앱에 둔다.

## 구현 방식 비교

| 기준 | CSS scroll-snap + 약간의 JS | JS transform (자체 구현 또는 embla) |
| --- | --- | --- |
| 터치 스와이프 | 브라우저 네이티브 관성·고무줄. 세로 스크롤과 다투지 않음 | 제스처를 직접 판별(`touch-action` 충돌) |
| 마우스 드래그 | JS 필요(스냅 잠시 끔) | 기본 제공 |
| 트랙패드 가로 휠 | 그대로 동작 | 직접 구현 |
| 키보드·포커스 | 포커스가 오프스크린 슬라이드에 가면 브라우저가 스크롤해 보여 줌 | 포커스 이동 시 직접 이동시켜야 함 |
| 페이지 내 검색·스크립트 없음 | 모든 슬라이드가 DOM·스크롤로 닿음 | JS 없으면 첫 슬라이드만 |
| 루프 | 복제 없이는 불가 → 끝에서 처음으로 **되감기**만 | 복제로 무한 가능, DOM 중복 |
| 이동 시간·곡선 | 브라우저가 정함(`behavior: "smooth"`), **토큰 통제 불가** | 토큰 값으로 통제 가능 |
| 의존성·크기 | 0 | embla 추가(~수 KB) 또는 자체 구현 수백 줄 |
| reduced motion | JS가 `behavior`만 고름 | 모든 전환 직접 끔 |

**추천: CSS scroll-snap.** 모바일 스와이프 품질과 접근성(포커스 스크롤, 무스크립트 도달)을 공짜로 얻고, 지는 항목은 루프(되감기로 대체)와 이동 시간 통제(수용)다. dg-design은 "새 의존성 없음·토큰만" 관례라 이쪽이 맞다.

## API

```tsx
import { Carousel } from "@dg-design/react/carousel";

export function Gallery({ images }: { images: { src: string; alt: string }[] }) {
  return (
    <Carousel.Root aria-label="작업 사진" slidesPerView={1}>
      <Carousel.Viewport>
        {images.map((image) => (
          <Carousel.Slide key={image.src}>
            <img src={image.src} alt={image.alt} loading="lazy" />
          </Carousel.Slide>
        ))}
      </Carousel.Viewport>
      <Carousel.Previous />
      <Carousel.Indicators />
      <Carousel.Next />
    </Carousel.Root>
  );
}
```

| Root prop | 기본안 |
| --- | --- |
| `value` / `defaultValue` | `number`(0부터, **첫 보이는 슬라이드의 위치**). 기본 0 |
| `onValueChange` | `(index: number) => void`. 위치가 바뀔 때마다 한 번 |
| `slidesPerView` | `number`(소수 허용, 1.2는 다음 슬라이드를 살짝 보임). 기본 1 |
| `align` | `"start" \| "center"`, 기본 `"start"` |
| `loop` | `boolean`, 기본 false. **되감기**: 끝에서 다음 → 처음, 처음에서 이전 → 끝 |
| `gap` | `"none" \| "small" \| "medium"`, 기본 medium (0 / `dimension-x2` / `x4`) |
| `motion` | `"auto" \| "none"`, 기본 `auto`. 모션 API 결정의 같은 이름 prop |
| 접근 이름 | `aria-label` 또는 `aria-labelledby` 필수 |
| 문구 | `roleDescription`(기본 "캐러셀"), `slideRoleDescription`(기본 "슬라이드"), `slideLabel(index, total)`(기본 `"3 / 5"`) |

- Root는 `role="region"`이 기본이고 `role="group"`으로 덮어쓸 수 있다(한 페이지에 여러 개면 랜드마크가 늘어난다).
- Viewport: 스크롤 컨테이너. 자식은 Slide만. div ref·속성 통과.
- Slide: `div`, `role="group"` + `aria-roledescription` + `aria-label`이 내부 소유.
- Previous / Next: `label`(기본 "이전 슬라이드" / "다음 슬라이드"), 기본 자식은 `ChevronLeftIcon`·`ChevronRightIcon`(`react/icon`), `children`으로 교체. 이름은 Pagination의 `Previous`/`Next`에 맞춘다.
- Indicators: `label`(기본 "슬라이드 선택"), `itemLabel(index, total)`(기본 "3번째 슬라이드로 이동"). 개수는 **스크롤 위치 수**(마지막 위치는 끝에서 멈춘 자리)다. 위치가 1개면 렌더하지 않는다.
- 값은 prop 존재 여부로 제어형을 가른다(Tabs 관례). 비제어 `defaultValue`가 범위를 넘으면 마지막 위치로 보정한다.
- 객체 `Carousel.Root/Viewport/Slide/Previous/Next/Indicators`와 named `CarouselRoot/CarouselViewport/CarouselSlide/CarouselPrevious/CarouselNext/CarouselIndicators`를 모두 export한다.
- `asChild`, 자동재생 prop, 세로 `orientation`, 반응형 `slidesPerView`는 첫 버전에 넣지 않는다.

## 동작

- Viewport: `display: flex; overflow-x: auto; scroll-snap-type: x mandatory; overscroll-behavior-x: contain; scrollbar-width: none`. Slide: `scroll-snap-align`은 `align` 따라, `scroll-snap-stop: always`로 세게 던져도 한 칸씩 멈춘다. 폭은 `slidesPerView`와 gap으로 계산한다(`--dds-carousel-*` 비공개 변수).
- **현재 위치 추적:** scroll 이벤트를 rAF로 모아 가장 가까운 스냅 위치를 구한다(`align`에 따라 슬라이드 시작 또는 중심과의 거리). 가까운 위치가 바뀌면 `onValueChange`. 위치 계산은 순수 함수로 빼 단위 테스트한다.
- **제어형:** 외부 `value`가 바뀌면 그 위치로 스크롤한다. 사용자가 넘겼는데 부모가 값을 갱신하지 않으면 스크롤이 멈춘 뒤 `value` 위치로 되돌린다(Sheet의 거절된 닫기와 같은 취급). 첫 렌더·`defaultValue`는 애니메이션 없이 맞춘다. 서버 렌더에서는 위치가 적용되지 않아 hydration 직후 한 번 맞추는 깜빡임이 있을 수 있다(수용, §상태 참고).
- Previous/Next/Indicator/키보드: `scrollTo({ behavior })`. `loop`이 아니면 끝에서 `aria-disabled`.
- Resize·slidesPerView 변경 뒤에는 현재 `value` 위치로 즉시 다시 맞춘다. RTL은 `dir` 계산값을 읽어 방향과 이전/다음 키를 뒤집는다.
- **터치:** 네이티브 스크롤에 맡긴다. 별도 제스처 코드 없음. 세로 스크롤은 페이지로 흘러간다.
- **마우스 드래그:** `pointerType === "mouse"`, 주 버튼만. 4px을 넘으면 끌기로 보고 포인터를 잡은 뒤 스냅을 잠시 끄고 `scrollLeft`를 따라간다. 놓을 때 놓기 직전 100ms 속도가 0.11px/ms를 넘으면 그 방향 다음 위치, 아니면 가장 가까운 위치로 스냅을 켜고 이동한다. 끌고 놓은 뒤 따라오는 click 한 번은 `onClickCapture`에서 삼킨다(슬라이드 안 링크가 열리지 않게). 문턱·속도·윈도 상수는 `use-drag-dismiss`와 한 곳에서 가져온다 — 지금 그 파일 안에만 있으면 구현 때 공용 모듈로 뺀다(값은 그대로). 끌기 중에는 `user-select: none`, 이미지는 `-webkit-user-drag: none`. 끝에서는 고무줄 없이 멈춘다(마우스 한정이라 단순하게).
- 슬라이드 안 `input`·`textarea`·`select`에서 시작한 포인터는 끌기로 잡지 않는다.

## 키보드·포커스 관리

| 입력 | 계약 |
| --- | --- |
| Tab | Previous → Viewport → (보이는 슬라이드 안 포커스 요소) → Indicators 정지점 → Next. DOM 순서를 따른다 |
| ← / → | **포커스가 Viewport 자신에 있을 때만** 이전/다음 위치. 슬라이드 안 입력의 방향키는 건드리지 않는다. RTL은 뒤집힘 |
| Home / End | Viewport 자신에 포커스가 있을 때 첫/마지막 위치 |
| Enter / Space | Previous·Next·Indicator 버튼 기본 동작 |
| Escape | 아무것도 하지 않는다 |

- Viewport는 `tabIndex=0`(스크롤 가능한 영역은 키보드로 닿아야 한다 — axe `scrollable-region-focusable`). 위치가 1개뿐이면 뗀다. 포커스 링은 비입력 관례대로 2px.
- **보이지 않는 슬라이드는 `inert`:** 교차 비율 0.5 미만인 슬라이드는 포커스·보조기기에서 빠진다. 포커스가 이미 안에 있는 슬라이드는 `inert`로 만들지 않는다. `inert`는 마운트 뒤에만 건다 — 서버 HTML과 스크립트 없는 환경에서는 모든 슬라이드가 닿는다.
- 슬라이드가 바뀌어도 **포커스를 옮기지 않는다.** Next를 누르면 포커스는 Next에 남는다.
- 끝에서 비활성이 되는 Previous/Next는 **`disabled` 대신 `aria-disabled` + `data-disabled`** 이고 클릭만 막는다 — Next를 눌러 마지막에 닿았을 때 포커스가 사라지지 않게 한다(Pagination 앵커 선례).
- Indicators는 `role="group"` 안의 버튼 N개. 현재 위치는 `aria-current="true"`. Tab 정지점은 하나(roving), ← →는 그 안에서 포커스만 옮기고 선택은 Enter/Space다(ToggleGroup multiple과 같은 취급).

## 자동재생

**첫 버전에 넣지 않는다.** 소비자가 제어형 `value`와 자체 타이머로 만들 수 있으나, 그러면 정지 버튼 같은 접근성 요구가 소비자에게 넘어간다. 사용 가이드에 WCAG 2.2.2(5초 넘게 움직이는 내용은 멈출 수 있어야 함)를 적는다.

도입하기로 하면 계약은 이렇다.

- `autoplay?: number`(ms) opt-in, 기본 꺼짐. `Carousel.Autoplay`(재생/정지 토글 버튼, `aria-pressed`, 필수 접근 이름) 없이는 동작하지 않는다.
- 자동 이동은 hover, 키보드 포커스가 Root 안에 있는 동안, 탭이 숨겨진 동안 멈춘다. 한 번 사용자가 넘기거나 정지하면 사용자가 다시 켤 때까지 재개하지 않는다.
- `prefers-reduced-motion: reduce`에서는 **시작하지 않는다**(켜 두지 않는 것이 기본). 정지 상태에서 시작해 버튼으로만 켠다.
- 자동 이동 중에는 상태 안내를 내지 않는다(아래 §접근성).

## 모션

- 이동: 브라우저 `behavior: "smooth"`(Previous/Next/Indicator/키보드/제어형 외부 변경). 시간·곡선은 브라우저 몫이라 `--dds-duration-*` 토큰을 쓸 수 없다. 이 예외를 문서에 적는다. `motion="none"` 또는 reduce에서는 `behavior: "auto"`(즉시). 판별은 JS의 `matchMedia`(Sheet·Toast 선례).
- 직접 조작(터치 스와이프, 마우스 드래그)은 reduce에서도 손가락·포인터를 따라간다 — 끌기 규칙 §5와 같다.
- 인디케이터 활성 전환: `background-color`·`border-color`를 `--dds-duration-fast` + `--dds-easing-out`으로. 색 전환이라 `motion` 밖이고 reduce에서도 남는다(조작 색 전환 결정). 크기는 바꾸지 않는다(레이아웃 속성 전환 금지).
- `transition-property`를 명시해 `all`을 쓰지 않는다. 새 duration·easing 토큰은 만들지 않는다.

## 토큰·치수

| 역할 | 기본안 |
| --- | --- |
| 슬라이드 간격 | `gap` 0 / `dimension-x2` / `dimension-x4` |
| Previous·Next | Button의 weak neutral + ghost 계열 재사용(Pagination 방식). 크기는 Button medium과 `--dds-size-touch-target` 중 큰 값(`max()`) |
| 인디케이터 점 | 지름 `dimension-x2`(8). 활성은 `bg-brand-solid` 채움, 비활성은 `stroke-neutral` 1px 테두리 + 투명 — 색만으로 구분하지 않는다 |
| 인디케이터 조작 영역 | 버튼 한 변 `--dds-size-touch-target`(데스크톱 24, 터치 44). 점은 가운데 |
| 포커스 | Viewport·Previous·Next·Indicator `:focus-visible` 2px `stroke-focus-ring` |
| 비활성 | Previous/Next: `aria-disabled` + `data-disabled` + 비활성 외관 3중 매칭 |

- 신규 토큰 없이 시작한다. 라이트·다크는 semantic만 참조하고 CSS는 `@layer dds`.
- 터치 44px 점이 많으면 폭이 넘친다. 375px에서 8개(352px)까지는 한 줄, 넘으면 줄바꿈한다. 슬라이드가 그보다 많으면 점 대신 소비자가 "3 / 12" 텍스트를 쓰길 가이드에 적는다.
- Viewport 높이는 슬라이드 내용이 정한다. 소비자는 이미지에 `aspect-ratio`를 줘 로딩 중 높이 변동을 막는다.

## 접근성

- Root `role="region"` + `aria-roledescription` + 이름, Slide `role="group"` + `aria-roledescription="슬라이드"` + `aria-label="3 / 5"`. 총 개수는 등록(`useOptionRegistry` 방식, DOM 순서) 뒤에 알 수 있어 **라벨은 마운트 뒤에 채운다.**
- **`aria-live`는 얹지 않는다**(dg-design 관례). Viewport에도 없다. 다만 Next를 눌러도 소리가 없으면 위치를 알 수 없어, Root 안에 시각적으로 숨긴 `role="status"` 한 곳에 `"3 / 5"`만 쓴다(암묵적 polite). 내용 전체를 읽히지 않는다.
  - 사용자 조작(버튼·인디케이터·키보드)으로 바뀐 때만 쓴다. 스와이프·드래그·자동 이동·초기화에서는 쓰지 않는다.
  - 실제 스크린리더 청취는 미검증이다. [후속 작업](../follow-ups.md)에 DatePicker QA와 함께 올린다.
- Previous/Next는 항상 DOM에 있어 포인터 없이도 모든 슬라이드에 닿는다. 마우스 드래그는 유일한 수단이 아니다.
- 인디케이터 버튼의 이름은 위치 번호만 담는다("3번째 슬라이드로 이동"). 슬라이드 제목이 있으면 `itemLabel`로 교체한다.
- 이미지는 소비자가 `alt`를 준다. 장식이면 `alt=""`.
- 대비: 점 테두리·채움은 배경 대비 3:1(WCAG 1.4.11)을 `pnpm generate`의 대비 검사 범위에 포함하거나 구현 때 수동 확인한다.

## 상태

| 상태 | 계약 |
| --- | --- |
| 슬라이드 0개 | 빈 Viewport만 렌더(높이 0). Previous/Next `aria-disabled`, Indicators 렌더 없음, 콘솔 오류 없음. 비어 있음 표현은 소비자(`StatePanel.Empty`)가 한다 |
| 슬라이드 1개 | 위치 1개. Previous/Next `aria-disabled`(loop이어도), Indicators 렌더 없음, Viewport `tabIndex` 없음, 스크롤 불가 |
| 슬라이드 수 ≤ `slidesPerView` | 1개와 같다 |
| 이미지 로딩 | 슬라이드 폭은 `flex-basis`로 고정이라 로딩이 폭을 흔들지 않는다. 높이는 소비자 `aspect-ratio`. 로딩 중 표현은 소비자(`Skeleton`). `loading="lazy"` 이미지는 가로 스크롤 영역 안에서도 근처에 오면 불러온다 |
| 슬라이드 동적 추가·삭제 | 등록이 바뀌면 개수·라벨·위치를 다시 계산. 현재 위치가 범위를 넘으면 마지막으로 보정(`onValueChange` 호출) |
| 제어형 값이 범위 밖 | 마지막 위치로 보정해 그리고 콜백은 부르지 않는다 |
| 서버 렌더 | 위치·`inert`·라벨은 마운트 뒤. 서버 HTML은 모든 슬라이드가 보이는 스크롤 영역이다. 클라이언트 경계는 다른 compound와 같게 처리 |
| 방향(dir=rtl) | 스크롤 방향·키·화살표 아이콘이 뒤집힌다 |

## 서버 컴포넌트·패키지

- 객체 + named export 둘 다(서버 컴포넌트는 객체 속성 접근이 안 된다). 서브컴포넌트 `displayName`은 `Carousel.Root` 형식.
- 하위 경로 `./carousel`(`dist/carousel/Carousel.js`)을 `package.json` exports에 더하고 `check:subpaths`를 통과시킨다. barrel(`src/index.ts`)은 감독이 직결한다.
- CSS는 컴포넌트 옆 파일 하나(`carousel.css`), 토큰 CSS는 import하지 않는다. 파일은 500줄 상한을 지킨다.

## 합격 조건

- [ ] 데스크톱 마우스로 4px 미만 이동은 슬라이드 안 링크를 정상 클릭하고, 끌고 놓은 뒤에는 링크가 열리지 않는다.

- [ ] role/aria-roledescription/이름/`aria-current`/`aria-disabled`를 단위 테스트가 검사하고 axe에 위반이 없다(`scrollable-region-focusable` 포함). `aria-live` 속성은 어디에도 없다.

## 열린 질문

각 항목의 첫 번째가 추천이다.

| 결정 | 선택지 (추천 먼저) | 영향 |
| --- | --- | --- |
| 자동재생 | 첫 버전 제외 / 정지 버튼 포함 도입 | 제외하면 §자동재생 계약만 예약. 도입하면 `Carousel.Autoplay`와 hover·포커스·reduce 테스트가 늘어난다 |
| `value` 형식 | 숫자 위치(0부터) / 슬라이드별 문자열 `value` | 숫자는 Slide에 prop이 필요 없다. 슬라이드가 앞에 끼면 위치가 밀린다. Tabs·ToggleGroup의 문자열 관례와 다르다 |
| 루프 | 되감기(복제 없음) / 복제 무한 루프 | 복제는 DOM·id·이미지 중복과 접근성 부담. 되감기는 한 번에 전체를 가로지른다 |
| 마우스 드래그 | 첫 버전에 포함(마우스 한정) / 버튼·키보드만 | 포함 시 JS 훅 하나와 click 삼키기. 제외하면 데스크톱에서 "끌리지 않는다" 인상 |
| 방향 | 가로만 / 세로 `orientation` 포함 | 세로는 키·스냅·RTL 매트릭스가 두 배. 소비처가 아직 없다 |
| 슬라이드 변경 안내 | `role="status"`로 "3 / 5"만 / 안내 없음 | 없으면 스크린리더 사용자가 넘김을 못 안다. 청취 검증 전이라 효과는 미확인 |
| Indicators 의미 | `group` + `aria-current` + roving 정지점 1개 / APG 탭형(`tablist`) | 탭형은 슬라이드가 `tabpanel`이어야 해 `slidesPerView > 1`과 1:1 대응이 깨진다 |
| 이동 시간 | 브라우저 `smooth` / 토큰 값의 JS 트윈 | 트윈은 스냅을 껐다 켜야 해 코드·버그 면적이 커진다. 대신 토큰 통제가 된다 |
| Previous/Next 배치 | 인라인(소비자가 className으로 배치) / 이미지 위 오버레이 기본 | 오버레이 기본은 레이아웃 가정이 늘고 `className` 우회가 필요해진다 |
| 반응형 `slidesPerView` | 숫자 하나(소비자가 `matchMedia`로 바꿈) / 브레이크포인트 객체 | 객체는 Tabs `responsive`처럼 DDS가 `matchMedia`를 소유한다. 첫 버전엔 과하다 |
