## 1. 메뉴 체크·라디오 항목

```tsx
<DropdownMenu.CheckboxItem checked={showGrid} onCheckedChange={setShowGrid}>격자 보기</DropdownMenu.CheckboxItem>

<DropdownMenu.RadioGroup value={sort} onValueChange={setSort}>
  <DropdownMenu.RadioItem value="recent">최근 순</DropdownMenu.RadioItem>
  <DropdownMenu.RadioItem value="name">이름 순</DropdownMenu.RadioItem>
</DropdownMenu.RadioGroup>
```

- `CheckboxItem`: `checked`(제어) · `defaultChecked`(비제어) · `onCheckedChange(checked)` · `disabled`. `role="menuitemcheckbox"` + `aria-checked`.
- `RadioGroup`: `value` · `defaultValue` · `onValueChange(value)`. `role="group"`(라벨은 `aria-label` 또는 앞의 `DropdownMenu.Label`과 `aria-labelledby`).
- `RadioItem`: `value` · `disabled`. `role="menuitemradio"` + `aria-checked`.
- 선택해도 **메뉴를 닫지 않는다** — 설정을 여러 개 바꾸는 흐름이라서다. 일반 `Item`은 지금처럼 닫는다. Escape·바깥 클릭·Tab은 기존대로 닫는다.
- 외관: 앞쪽 16px 표식 열(체크 아이콘·점). 선택 안 된 항목도 자리를 차지해 글자 시작선이 같다. 나머지는 `Item`과 같은 치수·상태(역할 토큰).
- 키보드: 기존 roving focus 그대로. Space·Enter가 토글/선택한다.
- ContextMenu는 같은 클래스·같은 컴포넌트를 `ContextMenu.CheckboxItem`·`RadioGroup`·`RadioItem`으로도 내보낸다.
- export: 객체 속성 + `DropdownMenuCheckboxItem` 등 named export(서버 컴포넌트 관습).

## 2. Select·MultiSelect 옵션 라벨 분리

```tsx
<Select.Option value="u42" label="김도걸" textValue="김도걸 디자인팀">
  <Avatar … /> 김도걸 <span>디자인팀</span>
</Select.Option>
```

- `label?: React.ReactNode` — 닫힌 트리거(MultiSelect는 칩)에 보일 표시. 없으면 지금처럼 children.
- `textValue?: string` — 검색 필터·타입어헤드에 쓰는 텍스트. 없으면 `label`(또는 children)의 텍스트. 칩 제거 버튼 이름은 지금처럼 `label`의 텍스트에서 나온다.
- children은 열린 목록의 행 표현으로만 쓴다.
- ③ 범위 밖: 옵션을 사용자 컴포넌트로 감싸면 첫 열기 전 트리거에 값 문자열이 보이는 한계(`internal/select-core.ts`)는 그대로다. `label`을 직접 배치한 Option에 주면 children 스캔이 이를 읽어 첫 열기 전에도 맞는 라벨이 나온다. 래퍼 사용처가 생기면 [후속](../follow-ups.md)대로 registry를 고친다.

## 3. DataTable 열 정렬

```ts
{ field: "amount", header: "금액", align: "end", sortable: true }
```

- `align?: "start" | "center" | "end"`(기본 start). 머리글·본문·필터 칸 모두에 적용.
- `end`면 머리글의 정렬 아이콘을 라벨 **앞**으로 옮겨 라벨 끝이 숫자 끝선에 맞게 한다(결정 기록 "표 정렬").
- 고정폭 숫자(`tabular-nums`)는 align과 별개라 소비자가 `cell`에서 고른다 — 끝 정렬이 늘 숫자는 아니다.
- 시안 `overrides/data-feedback.css`의 숫자 열 규칙(`:has(.fx-num)`)은 같은 커밋에서 지우고 시안 스토리는 `align: "end"`를 쓴다.

## 4. Toast action

```ts
toast({ title: "보관함으로 옮겼습니다", action: { label: "되돌리기", onClick: undo } });
```

- `action?: { label: string; onClick: () => void }`. 기존 `Toast.View`의 action 슬롯에 글자 버튼으로 렌더한다.
- 누르면 `onClick` 뒤 그 토스트를 닫는다.
- 자동 닫힘(5초, hover·포커스 중 정지)은 그대로다. 토스트의 행동은 사라질 수 있으므로 **같은 일을 하는 다른 경로가 화면에 있어야 한다**(WCAG 2.2.1) — 문서와 JSDoc에 적는다.

## 공통

- 동작은 테스트 먼저(vitest + user-event). 역할·aria 상태·닫힘 여부·제어/비제어·필터 텍스트·정렬 클래스·action 호출과 닫힘.
- Storybook: 각 컴포넌트 상태 매트릭스에 새 항목을 더한다(VR 대상). 기능 데모는 닫힌 상태 관습 유지. 시안 스토리는 새 API로 바꾸고 해당 덮어쓰기를 지운다.
- 배럴(`src/index.ts`)에 새 named export. changeset react minor.
- 검증: generate → build → test → typecheck → publint → 하위 경로 가드 → VR(CI). 메뉴 표식이 상태 매트릭스에 새로 생기므로 VR 기준을 CI로 갱신한다.

## 합격 조건

1. 스크린리더 트리에서 체크 항목은 menuitemcheckbox, 라디오는 menuitemradio이고 aria-checked가 상태를 따른다. 선택 뒤 메뉴가 열려 있다.
2. `label`을 준 Select Option은 닫힌 트리거에 label만 보이고, `textValue`로 검색된다. 주지 않은 Option은 기존과 같다(기존 테스트 전부 통과).
3. `align: "end"` 열은 머리글·본문이 끝 정렬이고 정렬 아이콘이 라벨 앞이다.
4. `toast({ action })`의 버튼을 누르면 onClick이 한 번 불리고 토스트가 닫힌다.
5. 기존 공개 API 동작 변화 없음.

## 결정 (승인 때)

- 체크·라디오 항목 선택 시 메뉴를 **열어 둔다**.
- Toast action이 있어도 자동 닫힘은 **5초 그대로**다.
