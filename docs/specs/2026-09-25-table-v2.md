## 공개 API 계약

- 새 `DataTable<T>`와 `DataColumn<T>`를 barrel과 `@dg-design/react/data-table` 서브패스에서 export한다. 기존 `Table` export는 유지한다.
- `data: readonly T[]`, `rowKey: Extract<keyof T, string> | ((row: T) => React.Key)`, `caption: string`을 필수로 한다.
- 열은 `columns: readonly DataColumn<T>[]` 또는 `children: ({ Column }) => React.ReactNode` 한 방식만 전달한다. 두 방식 모두 동일한 `DataColumn<T>`로 정규화한다. `Column`은 `field`와 `cell`의 행 타입이 `T`에 연결된다.
- 데이터 필드 열은 `field: Extract<keyof T, string>`·`header`를 갖는다. 계산 열은 `id: string`·`header`·`cell: (row: T) => React.ReactNode`를 갖는다. 공통 선택 prop은 `sortable`, `filter: "text" | { options: readonly { label: string; value: string }[] }`, `width?: number`, `pin?: "left" | "right"`다. 고정 열에는 `width`를 요구한다.
- `virtual?: false | { height: number; rowHeight: number; overscan?: number }`이며 기본은 `false`다. 가상화는 세로 행만, 고정 행 높이만 다룬다.
- 정렬은 한 열에 대해 해제→오름차순→내림차순→해제. 텍스트 필터는 대소문자를 무시하고 포함 여부로, 옵션 필터는 정확히 일치하는 값으로 처리한다. 정렬·필터는 현재 로드한 모든 행에 적용한 뒤 가상 범위를 선택한다.
- 상태 타입은 `DataTableSort = { id: string; direction: "asc" | "desc" } | null`, `DataTableFilters = Record<string, string>`, `DataTableSelection = readonly React.Key[]`로 한다. 공개 prop은 `sort/defaultSort/onSortChange`, `filters/defaultFilters/onFiltersChange`, `selectedKeys/defaultSelectedKeys/onSelectedKeysChange`로 고정한다. controlled 판정은 prop 존재 여부다.
- `selectable?: boolean`이면 첫 열에 체크박스를 추가한다. 머리글 체크박스는 현재 필터 결과 전체를 선택·해제한다(가상 화면에 마운트된 행만이 아님). 선택 ID는 `rowKey` 결과를 사용한다.
- `TableRoot`에는 스크롤 래퍼 속성과 ref를 전달할 수 있는 추가 prop을 둔다. 기존 table ref/className/HTML 속성의 대상은 그대로 `<table>`이다.

## 제약·하지 않을 것

- API 입력은 이미 로드된 배열이다. 서버 페이지네이션·무한 로딩·가변 행 높이·열 가상화·확장/트리/병합은 이번 범위에서 제외한다.
- 직접 자식 `<DataTable.Column>` API는 제공하지 않는다. 잘못된 필드명을 타입에서 놓치는 사용 방식은 허용하지 않는다.
- 기존 `Table` compound의 구조·ref·CSS·named export는 유지한다. 새 렌더러는 기존 CSS와 semantic token을 재사용하며 색 토큰을 추가하지 않는다.
- 정적 표에 불필요한 tab stop을 자동 추가하지 않는다. 가상 스크롤 영역은 이름 있는 포커스 영역으로 만든다.
- 커밋·푸시는 2026-09-25 사용자의 요청에 따라 진행한다. PR·배포는 별도 사용자 요청 전까지 실행하지 않는다.

## 남은 위험

- 네이티브 table 레이아웃, spacer 행, sticky 헤더·열의 조합은 브라우저에서 어긋날 수 있다. 소스 구현 전에 1만 행·고정 열 PoC로 시맨틱과 정렬을 검증한다.
- render prop의 fragment·배열·조건부 `null`은 명시적으로 정규화한다. 임의 래퍼 컴포넌트 내부는 읽지 않는다.
- 가상 행의 포커스가 화면 밖으로 이동할 때 포커스 소실 가능성이 있다. 키보드·보조 기술 브라우저 검증을 포함한다.
- `DataTable`은 Client Component다. 함수형 셀/열 선언을 서버 경계에서 직렬화할 수 없으므로 클라이언트 예제에 명시한다.

## 합격 조건

- [x] A/B 두 열 API에서 유효한 필드명과 `cell` 행 타입이 추론되고 잘못된 필드명은 typecheck 실패한다.
- [x] A/B가 같은 DOM·정렬·필터·선택 결과를 만든다. fragment·배열·조건부 열을 처리한다.
- [x] 정렬·필터는 원본 배열을 변경하지 않고, 선택은 정렬·필터 후에도 행 ID를 따른다.
- [x] 빈 데이터·필터 결과 0건에 접근 가능한 안내를 표시한다.
- [x] `virtual` 비활성은 전체 행을 네이티브 table로 렌더한다. 활성은 1만 행·480px·44px·기본 overscan에서 마운트된 실제 행 30개 이하이고, 화면 밖 셀 렌더러를 호출하지 않는다.
- [x] 위·중간·9,000번째 행으로 스크롤할 때 올바른 행을 보여주고 빈 구간이 남지 않는다. 정렬·필터 변경 시 스크롤 기준을 재설정한다.
- [x] 고정 헤더·좌우 고정 열이 가상화 켜짐/꺼짐, 375px/desktop, 라이트/다크에서 헤더·본문과 정렬된다.
- [x] caption, 스크롤 영역 이름·키보드 접근, aria-sort, 선택 체크박스 이름, 가상 aria-rowcount/aria-rowindex가 정확하다. 포커스 소실 시나리오를 브라우저에서 확인한다.
- [x] 기존 Table 테스트, 전체 build·test·typecheck·publint·VR이 통과하고 React 진단이 회귀하지 않는다.
