## 브라우저 실측

Storybook production build를 Chromium에서 확인했다. 가상화 예제는 1만 행, 480px viewport, 44px 행 높이, 기본 overscan 4를 쓴다.

- 9,000번째 행의 실제 `tr` 높이 **44px**, tbody 내부 위치 **8,999 × 44px ±1px**, 화면에 마운트된 실제 행 **20개**.
- 10곳으로 프로그램 스크롤한 뒤 첫 행 DOM 변경까지 4.2–17.4ms, 중앙값 16.6ms. 브라우저 이벤트·프레임 대기가 포함된 로컬 측정이며 기기별 성능 보증치는 아니다.
- 1만 행 이름 정렬을 클릭한 뒤 `aria-sort` 갱신까지 4.3ms(오름차순), 4.4ms(내림차순). 내림차순 첫 행은 사용자 10000으로 확인했다.
- 375px·500px에서 좌우 고정 열과 헤더/본문 x좌표·너비를 비교했고, 세로 스크롤 중 헤더 y좌표가 유지됐다. 375px 라이트·다크 화면을 수동으로 보았고, DDS Checkbox로 바꾼 뒤 다크 화면을 다시 확인했다.
- virtual 화면에서 선택 체크박스 포커스가 언마운트될 때 스크롤 region으로 이동하고, 원래 행으로 돌아오면 선택이 남았다. 비가상 표는 overflow가 있을 때만 이름 있는 region이 된다.

## 남은 검증

- Linux CI의 visual-baseline 워크플로로 신규 DataTable 스토리의 라이트·다크 기준 이미지를 생성해야 한다. 로컬 macOS에서 기준 이미지를 갱신하지 않았다.
- 실제 VoiceOver 등 스크린리더 청취 검증은 수행하지 않았다. 자동 브라우저 검증에서는 accessibility tree 동등성, 이름, 행 수/인덱스, 키보드 포커스를 확인했다.
- React Doctor 전체 스캔은 저장소 기존 진단 50건을 포함해 46/100이다. 새 `DataTable` 관련 진단은 없다. 변경 범위 스캔은 97/100·이슈 0건이지만 untracked 신규 파일을 포함하지 않으므로 전체 스캔도 따로 확인했다.
