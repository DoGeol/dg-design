# 끌어서 닫기와 Toast 재배치 결정

- 날짜: 2026-10-31
- 근거: [조작 색 전환 확대·Alert 진입 결정](./2026-10-31-motion-sweep.md)(§3에서 범위 밖으로 남긴 것), [컴포넌트 모션 API 결정](./2026-09-13-component-motion-api.md)(§6 reduced motion), [조작 모션·오버레이 퇴장 결정](./2026-10-28-interaction-motion-and-icons.md)(§3 퇴장 fast)
- 계기: 전수 조사에서 남은 세 건 중 두 건. 토스트는 가운데 하나가 사라지면 나머지가 점프했고, 시트는 백드롭 클릭·ESC로만 닫혔다.
- 상태: 활성

## 1. 끌어서 닫기 규칙은 한 곳에 — `internal/use-drag-dismiss`

Toast 가로 스와이프와 Sheet 손잡이는 같은 규칙이다. 두 번 쓰면 값이 갈라지므로 훅 하나로 둔다.

- 해제 판정: **대상 크기의 50%를 넘게 끌었거나**, 놓기 직전 속도가 **0.11px/ms**를 넘을 때.
- 속도는 조작 전체 평균이 아니라 **놓기 직전 100ms 구간**으로 잰다. 평균을 쓰면 빠르게 끌다 멈춰 생각하는 손가락이 해제로 읽힌다.
- 닫히는 반대쪽으로 끌면 거리를 1/3로 나눠 따라간다(고무줄). 하드 스톱은 "끝"이 아니라 "고장"으로 읽힌다.
- 4px을 넘기 전에는 끌기로 보지 않는다 — 토스트 안 닫기·되돌리기 버튼이 그대로 눌려야 한다. 끌고 놓은 뒤 따라오는 click 한 번은 `onClickCapture`에서 삼킨다.
- 훅은 거리(px)만 넘기고 무엇을 어떻게 옮길지는 컴포넌트가 정한다 — Sheet는 손잡이를 끌지만 움직이는 것은 Content다.

## 2. 멈춘 자리에서 이어 빠진다

손을 뗀 뒤 기본 퇴장 keyframes(`translateX(0)`에서 시작)로 넘기면 끌어 둔 거리만큼 되돌아갔다가 나가 번쩍인다. 그래서 해제 순간:

- Toast는 `data-swipe-out` + `--dds-toast-swipe-x`(멈춘 거리)를, Sheet는 `data-drag-out` + `--dds-sheet-drag-from`·`-to`를 단다.
- 퇴장은 그대로 **CSS 애니메이션**이다. `use-presence`가 계산된 길이를 읽어 언마운트를 기다리는 구조가 유지된다 — WAAPI로 바꾸면 그 배선이 둘로 갈라진다.
- 못 미친 경우의 스냅백만 WAAPI다(현재 위치에서 제자리까지, base 200ms). 인라인 위치는 손을 떼는 즉시 지우고 되돌아가는 그림만 애니메이션이 그린다.

## 3. Toast 세로 재배치는 FLIP — `internal/use-reorder-flip`

viewport가 flex column + gap이라 항목이 빠지면 나머지가 즉시 점프한다. 레이아웃은 최종값 그대로 두고 옮겨진 거리만큼 `transform`으로 되감은 뒤 제자리로 보낸다(150ms). `use-selection-indicator`와 같은 방식이고, WAAPI라 토큰 값을 코드에 적는 이유도 같다(CSS 변수를 못 읽는다).

순수한 위치 이동이라 **reduce에서는 걸지 않는다**.

## 4. Sheet는 손잡이에서만 끈다 — `Sheet.Handle`

Content 어디서나 끌리게 하면 시트 안 스크롤 영역(사내에도 DatePicker 달력 스크롤이 있다)·버튼과 싸운다. 그래서 공개 서브컴포넌트 하나를 추가했다.

- 장식이라 `aria-hidden` 고정이고 포커스를 받지 않는다. 키보드·보조기기는 ESC와 닫기 버튼으로 닫는다 — 손잡이는 추가 수단이지 유일한 수단이 아니다.
- 손잡이는 20px 남짓이라 4px 문턱을 넘기 전에 포인터가 밖으로 나간다. 그래서 손잡이만 **누르는 즉시 포인터를 잡는다**(안에 눌리는 것이 없어 click 가로채기 문제가 없다).
- side별로 축과 닫히는 쪽이 다르다. 상단 Sheet는 손잡이를 `order: 1`로 내려 화면 안쪽 변에 붙인다.

## 5. reduced motion

끄는 동안 손가락을 따라가는 것은 애니메이션이 아니라 직접 조작이라 reduce에서도 그대로 따라간다. 손을 뗀 뒤가 애니메이션이다:

- 해제: 가로·세로 이동 없이 opacity 페이드(`dds-overlay-fade-out`).
- 스냅백: 즉시 제자리(되돌아가는 것도 이동이다).

## 6. 하지 않은 것

- **StatePanel 로딩 → 본문 교차 페이드** — 본문은 소비 앱 코드라 라이브러리가 못 건드린다. 반쪽(패널 쪽 페이드)만 넣기보다 빼는 쪽을 골랐다.
- **Sheet 단계 전환 제스처**(fit → tall → full) — size는 소비자가 바꾸는 값이고, 끌어서 단계를 넘기려면 스냅 지점 정의가 따로 필요하다.
- **Toast 세로 스와이프** — viewport가 오른쪽 아래 한 곳이라 입장 축(가로)만 쓴다.

## 7. 검증과 남은 것

- `apps/visual-regression/tests/gesture-dismiss.spec.ts` — 거리로 해제, 천천히 조금 끌면 스냅백(둘 다 Toast·Sheet), 가운데 토스트를 닫으면 FLIP이 돈다. 판정은 거리로만 본다. 속도 규칙은 Playwright의 `mouse.move`에 지연이 없어 모든 조작이 "튕기기"로 읽혀 흔들린다.
- 단위 테스트는 `Sheet.Handle`의 접근성 계약만 본다 — jsdom에는 레이아웃도 포인터 캡처도 없다.
- **실기기 터치 QA는 못 했다.** `touch-action`(Toast `pan-y`, Handle `none`)으로 스크롤과의 다툼을 막았지만 실제 손가락으로는 확인하지 않았다. [후속 작업](../follow-ups.md)에 남긴다.
