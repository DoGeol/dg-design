# DatePicker 컴팩트 팝오버 결정

- 날짜: 2026-11-04
- 근거: [DatePicker 구현 결정](./2026-09-27-datepicker-implementation.md)의 "데스크톱 Popover는 24rem·두 달 가로 배치", [터치 기기 touch-target 폴백](./2026-11-01-touch-target-coarse.md)
- 계기: 데스크톱에서 달력 팝오버가 너무 크다는 요청. 날짜 칸이 모바일 기준 44px로 고정돼 팝오버가 384px(범위 688px)였다.
- 상태: 활성

## 결정

날짜 칸·이전/다음 버튼의 한 변을 `max(var(--dds-size-touch-target), var(--dds-dimension-x8))`로 잡는다. 마우스 환경은 24px와 32px 중 큰 32px, 터치 기기(`pointer: coarse`)와 모바일 밀도는 44px이다. 팝오버 폭과 월 `flex-basis`는 같은 값에서 계산해 칸 크기가 바뀌면 같이 변한다.

| 항목 | 이전 | 마우스 | 터치·모바일 밀도 |
|------|------|--------|------------------|
| 날짜 칸·이동 버튼 | 44px | 32px | 44px |
| 요일 행 높이 | 32px | 28px(`x7`) | 28px |
| 월 `flex-basis` | 308px | 224px(7칸) | 308px(7칸) |
| 단일 팝오버 폭 | 24rem(384px) | 258px | 342px |
| 범위 팝오버 폭 | 43rem(688px) | 498px | 666px |
| 패딩·월 간격 | x4·x4 | 그대로 | 그대로 |

- 폭 식은 `칸 수 × 칸 + 좌우 패딩 + 테두리 2px`(border-box)다. 테두리 2px을 빼면 범위 팝오버에서 두 달이 세로로 줄바꿈된다.
- 모바일 시트(47.99rem 이하)는 CSS 변경 없이 칸 높이만 같은 식을 따른다. 터치 폰은 44px, 마우스로 좁힌 데스크톱 창은 32px이다.
- 요일 행은 누르는 요소가 아니라 터치 기기에서도 28px로 줄었다.

## 왜 이렇게

- `@media (pointer: coarse)`를 컴포넌트 CSS에 복제하지 않고 이미 있는 `touch-target` 토큰을 읽는다. 터치 폴백 결정이 정한 방식(토큰 하나, 규칙 한 벌)과 같고, 밀도를 켠 앱도 같은 식으로 44px을 받는다.
- 태블릿처럼 터치 기기이면서 47.99rem보다 넓으면 팝오버를 쓴다. 이때도 칸이 44px라 모바일 44px 규칙(dg-studio DESIGN.md)을 지키고, 폭만 칸 수에 맞춰 줄었다(이전 384px에서 342px).
- 처음 제안한 단일 20rem·범위 36rem 대신 칸 32px 정사각에 맞춘 값(약 16rem·31rem)을 골랐다. 폭을 더 주면 칸이 가로로만 늘어 직사각형이 된다.
- 패딩(x4)·월 간격(x4)은 줄이지 않았다. 팝오버 안의 입력·프리셋·버튼 간격을 같이 흔들 필요가 없었다.

## 트레이드오프

- `pointer: coarse`는 주 포인터만 본다. 터치스크린 노트북을 마우스로 쓰면 32px 칸이다(WCAG 2.5.8 최소 24px는 만족, 44px 권장에는 못 미침).
- 날짜 칸의 터치 폴백은 `pointer`가 아니라 밀도·`touch-target`을 따르므로, 앱이 `touch-target`을 24px 미만으로 바꾸면 32px 아래로는 내려가지 않는다(`max`).
- 열린 팝오버의 VR 기준 이미지(단일·범위 데스크톱)는 크기가 바뀌어 CI의 visual-baseline로 다시 만들어야 한다. 모바일 시트 이미지는 마우스 환경이라 칸이 44px에서 32px로 줄어 같이 갱신 대상이다. 로컬에서 `-u` 하지 않는다.
- 검증: Playwright로 마우스·`hasTouch` 컨텍스트의 칸·이동 버튼 실측(32/44), 375px 시트와 1024px 터치 범위 팝오버 스크린샷 확인. 기능 테스트가 데스크톱 32px·폭 300px 이하와 터치 44px를 지킨다.
