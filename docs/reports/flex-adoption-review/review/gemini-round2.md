## 4. 합의와 남은 불일치

### 1) 합의된 사항 (Consensus)
1. **WCAG 1.4.11 비텍스트 대비 충족**: Box/Inbox 입력 및 DatePicker box 트리거에 1px 테두리(`stroke-neutral`)를 영구 복원하여 접근성 결함을 해소함.
2. **치수 근거 체계의 투명성**: 원문 직접 관측치(A/B등급)와 화면 간 교차 배율 추정치(C등급, 15개 항목)를 명확히 분리하여 기록함.
3. **토큰 파편화 방지**: Select 패널 반경을 신규 14px가 아닌 현행 DDS 토큰 규격인 12px(C등급)로 일치시킴.
4. **모바일 최소 터치 타깃 보장**: 단독 아이콘 버튼 및 Chip에 44x44px 터치 영역을 보장하는 안전망을 적용하고, 이를 차기 컴포넌트 API 정식 스펙으로 이관하기로 합의함.
5. **데스크톱 Chip 타깃 규격 인정**: 마우스 조작 환경에서 24px 높이는 WCAG 2.5.8 적합 예외임을 상호 확인하고 문서에 명시함.
6. **검토 정본의 위계 확립**: AI 생성 이미지는 전체적인 룩앤필을 보는 '무드보드'로 한정하고, 모든 규격과 치수, 접근성 검증의 단일 정본은 Storybook 컴포넌트 코드임을 확립함.

### 2) 남은 불일치 (Remaining Disagreements) 및 사용자 결정 질문

다음 4가지 핵심 쟁점은 기술적 정답이 아닌 제품 철학과 디자인 거버넌스의 선택 영역이다. 각 항목 끝의 한 줄 질문에 대해 사용자의 최종 결정이 필요하다.

#### ① 모서리 곡률 체계: A의 단일 6~8px vs B의 위계별 4~14px
- **대립 지점**: A안은 모든 요소가 6~8px로 통일되어 안정적이고 단정하다. B안은 입력/버튼(4px)은 단단하게 잡고, 서피스/패널(12px)과 모바일(14px)은 부드럽게 키워 시각적 위계와 밀도를 강조한다.
- **사용자가 정해야 할 한 줄 질문**:
  > *"전체 UI 모서리를 8px 단일 톤으로 통일해 차분한 일관성을 취할 것인가, 아니면 컨트롤(4px)부터 모바일·패널(12~14px)까지 위계별로 차등화해 물리적 층위와 밀도감을 살릴 것인가?"*

#### ② 폼 필드 표현 양식: A의 단일 Outline vs B의 Box + 속성 행 + Line 혼합
- **대립 지점**: A안은 모든 폼을 예측 가능한 Outline 박스로 일원화한다. B안은 텍스트 입력(Box), 선택 필드(속성 행 `>`), 메모(Line) 등 데이터 성격에 따라 외형을 차등화한다. B안은 풍부하지만 화면 내 복잡도가 증가한다.
- **사용자가 정해야 할 한 줄 질문**:
  > *"모든 입력을 단일 Outline 박스로 일원화할 것인가, 아니면 모바일 상세 화면 등에 속성 행과 하단 라인(Line)을 결합한 복합 폼 문법을 허용할 것인가?"*

#### ③ 브랜드 색상 주입 범위: A의 중립(Neutral) 절제 vs B의 적극적 주입
- **대립 지점**: A안은 브랜드 블루를 최종 제출(CTA) 버튼과 핵심 포커스에만 아껴 쓴다. B안은 필터 칩, 배지, 선택 상태, 아이콘 등에 브랜드 블루를 폭넓게 배치하여 생동감을 부여한다.
- **사용자가 정해야 할 한 줄 질문**:
  > *"브랜드 색상을 핵심 행동(CTA)에만 아껴 쓰는 절제된 중립 톤을 유지할 것인가, 아니면 필터와 선택 상태 전반에 적극 주입하여 경쾌한 톤을 만들 것인가?"*

#### ④ 모바일 1.75 배율 연쇄 철학의 시스템 규칙 채택 여부
- **대립 지점**: 작성자는 1.75 배율을 화면 전체의 조화로운 밀도 문법으로 간주한다. 비판자는 이를 특정 화면 관측치에 대한 과적합으로 보며, 시스템 수준의 강제 법칙으로 일반화하는 것에 반대한다.
- **사용자가 정해야 할 한 줄 질문**:
  > *"모바일 뷰포트 전환 시 1.75배율 기반의 통합 밀도 시스템을 정식 규칙으로 채택할 것인가, 아니면 표준 44px 터치 가이드라인 내에서 컴포넌트별로 유연하게 최적화할 것인가?"*

## 5. 디자인시스템 업데이트 권고 (Next Actions for DDS)

A안과 B안 중 어떤 안이 최종 채택되더라도, 이번 비교 검토를 통해 발굴된 성과를 dg-design 시스템에 즉시 흡수해야 한다.

1. **신규 컴포넌트 공식 편입 (B안 탐색의 핵심 수확)**:
   - **`Chip`**: Filter Chip(토글형), Input Chip(삭제형), Value Chip의 세부 역할 분리와 키보드 포커스 링 계약을 정식 컴포넌트로 승격.
   - **`PropertyField` (속성 행)**: 라벨-값 인라인 배치 및 오른쪽 disclosure indicator(`>`) 패턴을 공식 레이아웃 컴포넌트로 라이브러리화.
   - **`Bottom Sheet` 점진적 전개(Snap points)**: 모바일 환경에서 1단계(간단) → 2단계(상세) → 3단계(풀 스크린)로 이어지는 Sheet 인터랙션 모델 표준화.
2. **모바일 밀도(`density="mobile"`) 계약 공식화**:
   - 현재 임시 CSS 의사 요소(`::after`)로 적용된 44px 터치 영역 확장을 컴포넌트 내부 패딩 및 Hit-slop API 수준에서 구조적으로 보장하는 스펙 마련.
3. **토큰 스케일 무결성 및 거버넌스 강화**:
   - 10px, 14px 등 짝수 단위 간격과 반경은 DDS의 2px 스케일 내에서 공식 유효 토큰으로 인정하되, 홀수 토큰 및 불필요한 중간값 생성은 지속적으로 차단.
4. **다크 모드 부유 서피스 렌더링 2중 규칙 강제**:
   - Select, Popover, Menu, Dialog 등 부유 패널류는 다크 모드에서 `stroke-neutral-weak 1px` 테두리와 `shadow-overlay` 그림자가 누락 없이 함께 렌더링되도록 스타일 가이드 엄수.
5. **모바일 Select의 Sheet 자동 전환 (`gaps.md` #11 해결)**:
   - 모바일 뷰포트에서 Select 및 MultiSelect 패널이 좁은 팝오버로 뜨지 않고 하단 Bottom Sheet로 부드럽게 전환되는 반응형 오버레이 로직 구현.
