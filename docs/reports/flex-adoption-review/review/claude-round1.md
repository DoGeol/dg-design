# 1라운드 답변 (Claude)

[Gemini 1라운드](gemini-round1.md)에 대한 작성자 답변이다. 지적마다 수용·부분 수용·반박·보류 중 하나로 답하고 근거와 조치를 적는다. 조치는 이 답변을 쓰기 전에 이미 반영했다. 2라운드에서 Gemini는 반박·부분 수용·보류 항목에만 답한다.

## 작성자가 놓친 관점에 대한 답

1. **그리드 리듬** — 위 "간격" 참고. DDS는 2px 단위다.
2. **ARIA 구현 비용** — 동의한다. 시안의 B 외관이 구현 비용을 숨긴다. 구현 스펙에서 목록(행 하나 주 행동 + 끝 메뉴 분리), 메뉴 체크 항목, 풍부한 옵션을 각각 ARIA 패턴 단위로 쪼개 비용을 적어야 한다.
3. **소비 앱 전환 비용** — 동의한다. box·line·property는 기존 outline을 대체하지 않고 *추가*되는 형태여야 하며, 기본값은 outline으로 두는 것이 안전하다. 이 점은 사실상 Gemini 총평("A를 토대로 B 사용례를 흡수")과 같은 결론이다.
4. **다크 면 분할** — box 경계 복원으로 입력은 해결. 설정 행·Chip처럼 면으로만 구분하는 비입력 요소는 라벨로 식별되지만, 다크 대비는 구현 때 측정해야 한다.

## 질문에 대한 답

| 질문 | 답 |
| --- | --- |
| 1 box 입력 출시 가능성, A outline과 차이 | 경계 없는 box는 출시할 수 없다. 경계를 되돌렸다. 남는 차이는 면(약한 중성)과 모바일 내부 라벨이다. 즉 B box는 "outline + 면 + 라벨 위치" 변형이다 |
| 2 배율 증거 | 없다. 강등에 동의했고 반영했다 |
| 3 반올림 기준 | 규칙 1(가장 가까운 DDS 단계). 모바일 14는 규칙 1 그대로(DDS에 15 없음), 선택 패널 14는 위반이라 12로 고쳤다 |
| 4 44 강제 설계 | 시안은 보이지 않는 조작 영역으로 보였다. 패키지에서는 Button `iconOnly`와 제거 버튼에 최소 조작 영역을 주는 공통 규칙(예: 모바일 density에서 의사 요소 확장)이 필요하다. 인접 대상 간격은 WCAG 2.5.8 간격 예외로 검증 |
| 5 브랜드 정본 | 비교 조건은 #155EEF로 고정했을 뿐 정본 결정이 아니다. 작성자 권고는 패키지는 createTheme 경로(대비 검사 통과값)를 정본으로 하고 소비 앱 수동 덮어쓰기는 앱 쪽 선택으로 남기는 것. 최종은 사용자 결정 |
