# 38개 컴포넌트: 앞선 안과 원문 우선안

[비교 방법·근거](README.md) · [시각 비교](comparison.html)

A는 앞선 제안, B는 디자인 스킬·포니테일을 적용하지 않은 이번 판단이다. “유지”는 스킬이 없어도 결론이 같다는 뜻이다. 강한 조형 변경을 뒷받침할 원문이 없는 부품은 그대로 둔다. 구현 수준은 기존 [API 검토](../composition.md)를 함께 따른다.

## 입력·선택

| subpath | A → B | 실제 디자인 적용 |
| --- | --- | --- |
| `button` | 기존 세 크기 유지 → 대체로 유지 | 브랜드 CTA와 중성 보조 행동 구분. 페이지 헤더의 주 CTA와 본문 컨트롤을 같은 강조로 만들지 않음. 새 gradient/press motion은 추가 근거 없음 |
| `field` | 외부 label 기본, 내부 label 후보 → 용도별 표준 조합 | 폼 그룹/단독 입력/속성 값을 구분해 label·value·설명 위치를 각각 정의. 모든 배치를 같은 외부 label 폼으로 환원하지 않음 |
| `text-field` | box/line variant 검토 → 두 형태의 사용 목적 명시 | box는 여러 필드/버튼/속성의 조합, line은 단독·분절 입력. 둘 다 focus/error/도움말 연결 유지(M024–026) |
| `text-area` | TextField 스타일 공유 → box/line의 다중행 동등 지원 | label·설명·카운트·최대 높이 동작까지 같은 조합으로 정의. 높이를 단일 필드에 맞추지 않음 |
| `checkbox` | 기존 박스/브랜드 선택 유지 → 유지 | 단독 체크와 복수 선택 mark는 시각 관계를 맞추되 각각의 입력 의미를 유지 |
| `radio-group` | 기존 브랜드 원형, segmented 외형 후보 → 중성 설정 행을 추가 비교 | 약한 중성 행+중성 선택점과 브랜드 저장 버튼의 대비(DS026). 모든 radio를 중성으로 강제하지 않음 |
| `switch` | 우측 설정 행 → 미리보기와 결과 연결 강화 | 컨트롤 모양은 유지. 토글 값과 화면 결과/저장 경계를 한 조합으로 보여줌(서비스 설정 비전) |
| `slider` | 네이티브 range/값 표시 유지 → 같은 값과 결과 예시 연결 | 비율·타입 조절 등 실제 결과 미리보기를 곁들임. 새로운 slider 형태를 강제하지 않음 |
| `select` | 트리거 합성 후속 확장 → 다형 트리거를 핵심 설계 항목 | field형·버튼형·칩형에서 같은 값 선택 패널 사용. 장식보다 값 이해에 필요한 leading/trailing 슬롯 제공(DS018) |
| `multi-select` | 사각 mark·검색·선택수 → 대부분 유지, 문맥형 진입 확대 | 검색 가능한 선택과 toolbar chip의 진입을 함께 보여줌. 선택·hover 분리, 숨겨진 값 유지. A에도 이미 제안된 기능 |
| `date-picker` | presentation 확장 → inline/Popover/Sheet를 동등한 사용례로 | container와 달력 콘텐츠의 조합을 먼저 검토. 기존 Calendar/Field/값 모델 재사용(M027–029) |
| `file-input` | Dropzone/Preview 정렬 → 대체로 유지 | 글의 근거로 전용 업로더 외형을 새로 확정할 수 없음. 문서/댓글 속 첨부 위치에 따라 조합 |

## 탐색·메뉴

| subpath | A → B | 실제 디자인 적용 |
| --- | --- | --- |
| `tabs` | 밑줄형/overflow 후보 → 페이지 문법과 결합 | 제목·주 CTA·검색/필터와 함께 배치. active/hover/focus는 유지. manual activation을 flex 필수값으로 보지 않음 |
| `dropdown-menu` | Sub 중심 보완 → 보조 영역/설정 명령까지 조합 명세 | header/footer, 그룹, shortcut, check/toggle, Sub의 표현 구분(DS021–023). 자의적 interactive 중첩은 허용하지 않음 |
| `context-menu` | Dropdown 스타일 공유 → 유지 | 원문 기반으로 별도의 우클릭 스타일을 만들 근거 없음. 동일한 행동을 명시적 트리거로도 제공 |
| `breadcrumb` | 제목 위 경로 → Page Navigation 맥락 강화 | 경로·뒤로가기·페이지 제목의 관계를 정의. 별도의 숫자 토큰 변화는 없음 |
| `pagination` | 기존 크기 유지 → 유지 | 페이지/표 탐색 정책은 데이터에 따라 결정. 원문 스타일을 이유로 무한 스크롤로 일괄 교체하지 않음 |
| `accordion` | 기존 밀도/헤더 정렬 → List 그룹과의 역할 분리 | 일반 본문 disclosure는 유지하고 목록 그룹 제목의 접기/추가 행동은 별도 ListSection 조합으로 다룸 |
| `collapsible` | 부가 정보 펼치기 → 유지 | 새 조형의 직접 근거 부족. 무엇을 감추고 어떻게 다시 여는지 과업 맥락을 따른다 |

## 표면·레이어

| subpath | A → B | 실제 디자인 적용 |
| --- | --- | --- |
| `dialog` | 확인형 유지·작업형 부품 → 작업형의 보기 체계 우선 정의 | Toolbar, title/content, 본문 Footer, optional Aside를 중앙/측면/전체 보기로 조합(DS008–011). 확인형은 계속 간단하게 |
| `sheet` | content-fit/full와 safe area → 맥락을 유지하는 전환 규칙 추가 | 같은 컨테이너에서 선택→확인→상세/전체 보기의 값·뒤로가기·닫기 정의(M031). 웹에서 네이티브 제스처를 자동 복제하지 않음 |
| `popover` | 기존 p16/r12 유지 → 담는 기능에 따른 표현 분리 | 정보·선택·설정 컨테이너를 같은 padding 공식으로 묶지 않음. portal·focus·경계 계약은 동일 |
| `hover-card` | 작은 객체 미리보기 → 유지 | 문맥 정보의 양을 먼저 정함. 원문만으로 새 hover motion이나 shadow를 확정할 근거 없음 |
| `tooltip` | 기존 작은 반전 표면 → 유지 | 설명 범위·접근 이름 계약 보존. 꾸밈 차이를 만들 이유 없음 |
| `card` | 기본 r12/p16, 평면 List와 구분 → 유지 | B에서 List를 먼저 설계하므로 카드가 객체 목록의 기본 대안이 되는 경우가 줄어듦 |
| `separator` | 간격 우선/필요한 경계 → 문맥별 경계 판단 | 그룹 여백의 고정 2배 규칙을 요구하지 않음. 원문 메뉴·모달에 존재하는 경계선도 역할에 맞게 유지 |

## 데이터·피드백

| subpath | A → B | 실제 디자인 적용 |
| --- | --- | --- |
| `table` | 비교용 표/기존 여백 유지 → 유지 | 객체 탐색은 List, 다열 비교는 Table. 행마다 카드처럼 만들지 않는 결론은 같음 |
| `data-table` | density/API 보완 → List와 표의 선택 기준을 먼저 검토 | 필터/정렬 toolbox는 앱 조합. 가상화 높이·고정 열 계산 일치라는 구현 조건은 동일 |
| `avatar` | 기존 크기/원형 유지 → 목록 leading의 표현 범위 확대 | 이미지·아바타·도메인 표식 슬롯으로 구분. DS014의 다양한 객체 표현을 모든 leading이 원형이어야 한다는 규칙으로 축소하지 않음 |
| `badge` | 비대화형 상태 표시 → 유지 | 상태 Badge, 선택 Chip, 코드/보조 표식을 구별. 의미 없는 색상 추가는 근거 없음 |
| `notification-badge` | dot/count 유지 → 유지 | 글로벌 알림·객체 상태를 구분해 배치. 원문에서 독자 숫자 스케일을 복원하지 못함 |
| `alert` | 기존 안내/actions 정렬 → 폼 과업 안 배치 강화 | TextField/PropertyField와 함께 정책·주의·복구 정보를 배치. 새로운 의미색 팔레트는 필요하지 않음 |
| `toast` | 현 밀도/live region 유지 → 유지 | 원문 근거 부족으로 외형 변경을 확정하지 않음. 결과 피드백이라는 역할과 기존 동작 보존 |
| `state-panel` | empty/error/loading 조합 → 유지 | 과업별 문구와 다음 행동을 정함. 새로운 장식이나 그림을 요구할 근거 없음 |
| `save-status` | 저장 상태·업무 상태 분리 → 유지 | 서비스 글의 처리/완료 구분과도 일치. 디자인 스킬의 유무로 달라지지 않음 |
| `progress` | track6/값·문구 → 유지 | 새로운 수치/모션을 정할 직접 근거 부족. 가짜 완료율을 표시하지 않는 조건도 동일 |
| `spinner` | 16/20·기존 회전 → 유지 | 크기·easing 교체 근거 없음. 브랜드 강조 여부는 처리 문맥에 따라 결정 |
| `skeleton` | 실제 콘텐츠 구조 예고 → 유지 | 특정 flex Skeleton 스타일을 추출하지 않았으므로 기존 DDS와 대상 행 구조 사용 |

## 새 종류의 우선순위

| 후보 | A | B |
| --- | --- | --- |
| List / SectionHeader | 추가 검토 후보 | 첫 설계 묶음. 행의 기본 행동, 액세서리, 그룹 제목, 선택 모드를 함께 정의 |
| Chip / Filter toolbox | private chip 추출, 앱 조합 우선 | 표시값/제거/필터 진입의 역할을 우선 정의. toolbox에는 결과 수·초기화·고정/제거 가능 조건을 문서화 |
| PropertyField | 버튼형 선택 트리거 후보 | 모바일 폼의 동등한 입력 종류. label/value/accessory와 실제 picker 연결을 설계 |
| 모바일 조합 | 기존 부품에 밀도/height 보완 | 허용한 액세서리·label·value·행동 배치를 사전 조합 예제로 제공 |

이는 설계 우선순위이며 공용 API를 무조건 새로 만들라는 결론이 아니다. 두 실사용처·안정 API가 필요한 프로젝트의 승격 규칙은 계속 적용된다.
